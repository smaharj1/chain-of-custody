# v2 pending human actions

This is the list of things 2.0.0-rc.1 needs a person to do before it can be called 2.0.0, or before a given feature is safe to switch on. It is built from the "Pending-human actions" sections of the per-topic fragments in `changelog.d/` and from the release notes of the build.

Nothing in this file was done by an agent. Each item says why an agent could not do it: it needs a network or a GitHub login, a credential, a live `claude` session (the scripts refuse to start `claude` for you), a real project or a decision that belongs to a maintainer. Tick an item when you have done it, and record any result that overturns an assumption in `docs/design/probe-results.md` (copy `docs/design/probe-results.template.md`).

Run the commands from a plain terminal, not from inside a Claude Code session. The scripts that change GitHub or the kit refuse to run in one.

## 0. Repository hygiene (do first)

- [ ] **Delete the stray file `.git/loopctl/events/s-s1.jsonl` in the main checkout.** A builder's early manual run created it and the sandbox refused its delete. Look at it (`cat .git/loopctl/events/s-s1.jsonl`), then `rm .git/loopctl/events/s-s1.jsonl`. Why not an agent: it is runtime state under `.git`, and the guards and sandbox deny agent writes there.
- [ ] **Push the v2 branches and open the PRs.** `git push -u origin <branch>` for each `v2/*` branch you want reviewed (`git branch --list 'v2/*'`), then `gh pr create --draft --base main --head <branch>`, or merge `v2/integration` by your usual route. The kit's own PR cannot pass the `verify` check (the base has no `verify.py`), so merge it by hand. Why not an agent: agents never push or open PRs (guard rule `guard-git:push`).
- [ ] **Push the baseline tag.** `git push origin v1.2.0`. The tag exists locally on `cb6218f`; the baseline harness and `.claude/migrate/v1.2.0.tar` check read it, and `tests/dist/test_build.py` compares the archive with it only when the tag is present. Why not an agent: it is a push.
- [ ] **Run the full suite and the release checks once on your machine:** `tools/test.sh`, `python3 tools/check-refs.py`, `python3 tools/build-dist.py --check`, `python3 tools/validate-plugin.py --strict`. Add `fetch-tags: true` and `fetch-depth: 0` to the `kit-tests.yml` checkout so the tag comparison runs. Why not an agent: the CI file is a workflow, and the first run is on GitHub.

## 3. Guards: confirm they are live

2.0.0-rc.1 wires the v2 guards in `.claude/settings.json` and removes the v1 hooks `guard-git.sh` and `guard-main-edit.sh`. If your `settings.json` still names those two scripts, the switch has not happened in your copy. These checks need a live session.

- [ ] **Run the checks:** `python3 .claude/scripts/guards/wiring.py --check`, `python3 .claude/scripts/doctor.py` (`guards.v1-residue` must pass), then `python3 .claude/scripts/guards/run.py --selftest --record`. Start a new session and look for the `kit session_start: canary session=... nonce=...` line. No line means the hooks are not firing.
- [ ] **Probe V9 on the pinned CLI:** that `onFailure: block` is honoured and where it goes in the hook entry (the guards also fail closed by themselves). Probe V1 (`agent_id` and `agent_type` in hook input at depth 2 and 3) decides how much the caller classification can be trusted.
- [ ] **Register the prose-loop conductor** if you use the prose `/orchestrate` loop: `python3 .claude/scripts/guards/run.py register-session --role conductor --session <id>` (human only; the driver and `loopctl begin` register themselves).
- [ ] **Check that a sandboxed Bash command cannot create a file under `<git-common-dir>/loopctl/sessions/`** and that SessionStart still writes nonces (hooks are assumed not to be sandboxed [probe V19]).
- [ ] **Read `docs/security/guards.md` "What the guards cannot see"** and decide whether any gap needs a platform control.
- [ ] **Re-run the hello-loop against the live hooks and the live evals** (`claude plugin eval`); the synthetic evals prove only the graders and the replay.
