# Changelog

All notable changes to Chain of Custody. Format follows [Keep a Changelog](https://keepachangelog.com/); versions are recorded in `.claude/KIT_VERSION` of every installed copy.

## [Unreleased]

### Cross-reference + ownership audit (July 2026)
- **Engineer verify commands moved to the primers.** Four agent files (`backend`, `app`, `admin-app`, `infra`) shipped placeholder verification commands (`lint .`, `test .`, "adjust to match your project") inside files the README declares never-edit and safe to overwrite on kit update — so no role owned filling them in, and the primer-derivation machinery didn't cover them. The domain primers now carry a `## Verification Commands` template section (proven-by-running, per primer-protocol), and the agent files point at the primer as source of truth — the pattern `database-engineer.md` already used. Infra points at its primer's existing Deploy Commands validate/preview lines instead of duplicating them.
- **Permission prompts documented for loop runs.** Claude Code's own permission gate sits underneath the autonomy dial: an `unattended` run stalls at the first un-allowlisted command, and no doc mentioned it. Now covered in README Prerequisites, a new FAQ entry ("The loop keeps stopping to ask permission"), an orchestrate preamble check (step 5 warns on an empty allowlist before a `per-milestone`/`unattended` run), and a Planner Phase-2 offer to allowlist the run/test commands as a plan output. The shipped allowlist stays empty by design.
- **Broken pointers fixed.** engineer-protocol's report format sent `## Primer Delta` readers to "section 12" (Domain Quality Bars) instead of §11; `planner.md` and `primer-protocol.md` still said greenfield `TODO(primer)` markers get filled at "Orchestrator step 6" — orchestrate renumbered that work to 5.5 (step 6 is Update + log). Both now use the current numbers.
- **security-reviewer contract reconciled with its verdict.** Leftover imported voice removed ("STAY IN CHARACTER as SecureGuard") and the ALWAYS/NEVER lists rewritten in verdict language — the old "Block deployment" / "NEVER approve code with unpatched vulnerabilities" contradicted both the agent's read-only role and the Critical/High-only blocking rule (Medium/Low findings are reported, not blocking).
- **Papercuts.** `CLAUDE.md`'s H1 was entirely an HTML comment (rendered as an empty heading) — now a visible placeholder with the sentinel comment below it; its roster prose moved `infra` into the engineer list (Tech-Lead A.2/A.3 dispatches it with briefs and reports like any engineer); tech-lead's "all nine" primer count corrected; GLOSSARY's Security Reviewer entry now mentions the loop's auto-dispatch; getting-started notes `docs/design/review-2026-07.md` is skippable internal history; engineer-protocol's opening clarifies it's a shared rulebook, not an agent definition (agent definitions live in `.claude/agents/`).

### Primer access + freshness: `## Primer Delta` in every report
- **The read path was the vaguer half.** Five of six engineer agent files said "Any backend context docs in `.claude/context/`" — the one file that knows the concrete filename gave the least concrete instruction, to a subagent in a clean context that can't infer it. `design-critic` said "Any architecture context docs." All now name the exact path, state that it's read **before** the brief on every dispatch, and say why: the primer holds the canonical exemplar the diff will be reviewed against. Frontend engineers are pointed at `shared-frontend.md` alongside their own.
- **Nobody could report a stale primer.** The strict report format had no field for it, so the Tech Lead had to *infer* a primer delta from a file list — while the engineer, the one role that had just discovered the primer was wrong, had nowhere to say so. New **`## Primer Delta`** section in the report format plus engineer-protocol §11: report a new pattern, a dead exemplar pointer, a convention the codebase moved off, or a primer that had nothing for your area. **Engineers report but never edit** — one slice, one clean context, a shared file that parallel engineers would collide on; canon is written by the role holding the whole picture. The delta travels as an artifact, like everything else in this kit.
- **A stale primer used to block correct code.** Code-review dimension 6 made "invented a pattern" a finding with no way to conclude the *primer* was the stale thing — so correct code got blocked and re-dispatched to match a dead convention. The reviewer now checks the primer's claim against the surrounding code first and reports `## Primer Staleness` instead of a blocker.
- **Application is now explicit at every wrap point**: Tech Lead A.8 step 5 (apply the reports' deltas, don't infer them), the quick lane's new B.3 step 4 (where a styling convention gets set with no design doc to record it), and the Orchestrator's 5.5 — which also closes out `TODO(primer)` markers the item resolved, since that's the only thing that lifts the autonomy downgrade, and logs `primersUpdated` per item so an unbroken run of empty deltas is a visible drift signal.

### Primers are agent-written now — the setup questionnaire is gone
- **The premise was wrong.** README step 2 asked the user to hand-fill ten files — `CLAUDE.md`, eight context primers, `loop.config.md` — including an ORM, an endpoint catalog, a layering pattern, and a canonical exemplar per layer. This kit's stated audience includes people who don't know what an ORM *is*. Worse, an unfilled primer failed silently in a way the user couldn't diagnose: `/orchestrate`'s sentinel grep quietly downgraded autonomy to `per-feature` for the life of the project, so the loop that was supposed to run unattended asked for a checkpoint at every single item.
- **New `.claude/context/primer-protocol.md`** — generic kit logic alongside `engineer-protocol.md`, and the single source for how primers get written: derive from evidence in the repo (manifests, import direction, real files) not from memory; never assert what the code doesn't show; catalogs point at source-of-truth files; **execution-critical commands get run once before being written down**, since a plausible wrong test command surfaces later as a mystery hard-stop. Plus the rule that made the whole change necessary: *never ask the user a technical question* — ask plain-language product questions only, make technical calls yourself, and record what each one rests on.
- **Ownership is now explicit per role.** Planner writes the primers plus `local-dev.md` + `loop.config.md` as plan outputs (new Phase 2b); Orchestrator's preamble derives what the run needs instead of printing a to-do list; Architect derives the domains it's about to design for (new Phase A.0); Tech Lead derives a domain primer before dispatching an engineer into it, and — changed — **updates the primer itself at wrap-up** rather than recommending the user go invoke `/architect`; PM notes gaps and authors nothing, since it defers technical authority.
- **`TODO(primer)` keeps its teeth.** Derivation can't invent an exemplar for code that doesn't exist yet, so greenfield primers still ship with marked gaps and autonomy still downgrades — but now only for what is *genuinely unknowable*, with the reason reported, and the gap closes when the baseline item ships. The readiness grep skips the two protocol files, which quote the sentinels by design (a self-trip would have pinned every project at `per-feature` forever).
- **README**: step 2 deleted; the Quick Start is three steps, only the first required. A new **"How the Agents Learn Your Project"** section carries the file table, reframed from *what to put in it* to *who writes it and when*. "Which files to edit" became "review, don't author." The copy-paste "read this codebase and draft each primer" prompt is gone — that's the Architect's Phase A.0 now, not a thing the user pastes.

### Renamed: Chain of Custody
- The project is now **Chain of Custody** (was "Claude Code AI Engineering Team"), tagline *"a role-based engineering team for Claude Code, where written specs are the only thing that crosses between agents."* The name points at the load-bearing mechanism rather than the org chart: every agent runs in a clean context, so the artifact is the only thing that crosses a boundary — each role takes possession, signs off, and hands on, and the trail is auditable.
- Updated the README title and opening, the `getting-started.md` intro, the GLOSSARY preamble, and the clone paths in the install manifest (`/tmp/ai-team` → `/tmp/chain-of-custody`). Generic references to "the kit" were left alone deliberately — they read better than repeating the proper noun.

## [1.1.0] — 2026-07-18

Full remediation of the July 2026 review ([docs/design/review-2026-07.md](docs/design/review-2026-07.md)).

### Loop runtime (state machine)
- **`needs_review` status deleted.** Checkpoints are now run-level `loop.jsonl` records; a checkpointed item stays `done` (it was already merged — the old status overwrote `done` and stranded items on session death).
- **Every item-level hard-stop now sets `blocked` + `blockReason`**, and a new preamble **unblock review** is the sanctioned recovery path (reset to `pending` / keep / route to `/planner`). Security stops gain a user-grantable `securityWaiver` field.
- **Checkpoints gained three exits**: approve / **reject** (revert merge + run the item's down-migration + reset to `pending` with `reworkNotes`) / stop. A failing demo route is `DEMO_FAILED` — a forced checkpoint.
- **Durable-DB migration step**: after each merge the conductor applies the item's migrations to the durable dev DB (new `migration_failed` hard-stop); down-migrations are recorded as `downMigrationRef` on the item.
- **Run counters re-derived from `loop.jsonl`** (`run_start` records + `breaker` flags) so the circuit breaker genuinely survives resumes; run lock replaced with a heartbeat lock (pid-based liveness could not work — each Bash call is a fresh shell).
- **Pass-path write ordering fixed** (single JSON update after merge) + reconciliation now recovers merged-but-unrecorded items from git log.
- **Preamble step 0**: `git init` on an empty folder; loop-mode briefs are written to disk and requirements passed inline (design-critic and templates updated to match).

### Hooks
- `guard-git.sh`: now **allows `git branch -D feat/*`** (the loop's own fail path needed it); blocks the ordinary-form bypasses (newline-chained commands, `FOO=1 git push`, `command git push`, `&&` without spaces, subshells); announces itself inactive if python3 is missing. 16-case test battery in the review doc.
- **New `guard-main-edit.sh`**: blocks Edit/Write to app source while on `main`/`master` (path-allowlisted for kit/plan/docs files) — the hook two docs referenced but the kit never shipped. Wired in `settings.json`; Tech Lead now runs a branch check before dispatch.

### Bootstrap safety floor (greenfield)
- Planner fills `loop.config.md` verify commands as a **plan output**; greenfield first item stamps `CLAUDE.md`'s stack table (kills the perpetual autonomy downgrade); Tech-Lead A.2 gains a scaffold ownership row (Backend owns the skeleton). A dedicated bootstrap mode remains deferred (§14).

### Docs
- README caught up with the loop layer: file tree, setup checklist (adds `local-dev.md` + `loop.config.md` — the old checklist guaranteed a first-run hard-stop), explicit install manifest, install-collision warning, existing-codebase primer-generation recipe, three-tier Prerequisites (context7 install-name trap documented), greenfield/existing fork in Quick Start.
- GLOSSARY gained the loop vocabulary, git-for-beginners terms, and environment terms; getting-started gained the checkpoint/push walkthrough and honest fill-in claims.
- Design doc Revision-2 staleness fixed (§2 Skill/Agent split, §8 security gate condition); `token_budget` renamed `tool_call_budget` in the brief/protocol layer; brief/report filenames standardized on domain shortnames; stray duplicate headings and wrong-direction references removed; security-reviewer description rewritten (no more auto-delegation bait).
- New **[docs/faq.md](docs/faq.md)**: testing strategy, CI, deployment cliff, monorepo/polyrepo, teams, abandoning items, test-count parsing, non-web rosters.

### Examples
- `examples/` is now actually complete: all 8 context primers (including the load-bearing `local-dev.md` with a concrete verify-run harness and Postgres-ephemeral variant), a filled `loop.config.md`, and a full example feature folder (`examples/features/csv-export/`). Fixed the database example's own convention violations (`onDelete`, `updated_at`).

### Packaging
- Added LICENSE (MIT), this CHANGELOG, `.claude/KIT_VERSION`, a README "Updating the Kit" section (never-edit vs user-owned file sets), `.gitignore` coverage for loop artifacts, and removed shipped `.DS_Store`/`worktrees` artifacts.

### Known accepted limitations (unchanged by design)
- `echo git push | sh` bypasses guard-git (adversarial form; allow-on-uncertainty is the documented policy).
- The hooks cannot distinguish engineer git writes from the conductor's — that boundary remains protocol convention.
- Read-only critic agents technically hold `Bash`; the read-only constraint is prompt-level.
- Mobile has no simulator auto-demo; demo targets fall back to text assertions.
