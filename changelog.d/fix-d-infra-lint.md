# fix-d-infra-lint: infra CI lint and doctor strictness (review findings IN-1 to IN-9, IN-11 to IN-15, GT-12, DEC-1)

## Changes

Rule: anything that can put a credentialed, deploy-class job behind a gate the lint cannot verify is an error; things that only hide intent in a job with no credentials stay warnings. No path was loosened, and nothing here lets an agent apply infrastructure: a person still approves every apply (H4).

- **IN-1, non-main pushes (`ci_rules.bot_reachable`, `workflows.push_main_only`).** A `push` that is not main-only (any other branch, `**`, `branches-ignore`, tags, no filter) is bot-reachable, like the pull-request events. `infra.plan-ungated` uses it. New rule `ci.credentials-on-bot-push` (error): a job with OIDC, a credential action, a stored cloud key or any non-`GITHUB_TOKEN` secret that such a push starts, with no static `environment:`. The doctor (`deploy.py`) now counts a credentialed job on `push:branches` or a tag as a deploy, so B5 caps the level at L1.
- **IN-2 and IN-6, vocabulary and command words.** `sam deploy`, `cdktf deploy`, `pulumi up|update|destroy`, `terragrunt run --all apply`, `terragrunt run-all apply`, `copilot [svc|env|job] deploy`, `eb deploy|create|terminate`, `serverless|sls deploy`, `ansible-playbook`, `gruntwork-io/terragrunt-action`, `dflook/tofu-apply`, `dawidd6/action-ansible-playbook` are applies, in both `ci_rules` and the doctor scan. `workflows.normalize_shell` reads a command word through `/usr/local/bin/terraform`, `./bin/tofu`, `terraform 'apply'`, `$(which terraform)`, `` `command -v tofu` ``, `${TF:-terraform}`, a backslash inside a word, `TF=terraform` set in the same script, and a container tag or digest (`docker run hashicorp/terraform:1.9 apply`). A command word that is still a bare `$VAR`, `${VAR}`, `"$VAR"` or `$(...)` before `apply|destroy|deploy|up` is `infra.apply-indirect`: an error in a credentialed job, a warning elsewhere. A workflow whose only infra signal is such a command in a credentialed job is now treated as an infra workflow.
- **IN-3, `docker://`.** `ci.docker-uses-unpinned` (error with credentials, warning without) for an image with no `@sha256:` digest. A docker step is read as its `entrypoint` and `args`; a known IaC image (terraform, tfc-agent, opentofu, terragrunt, pulumi, kubectl, helm, aws-cli, or a repository name containing terraform/tofu/terragrunt/pulumi/kubectl/helm) with no args, or args computed at run time, is deploy-capable. `ci.deploy-in-pr-job` and the doctor read docker steps the same way.
- **IN-4, Environment approval.** `infra.environment-approval-unverified` is an error. `levelcalc.env_reviewers_available` now asks about the Environment each apply job names (new `deploy.apply_jobs`): true only if every one exists with required reviewers in the recorded GitHub data; an apply job with no static environment is not credited; with no GitHub data the `environment_reviewers` attestation stands; a repo with no apply job keeps the old "some Environment has reviewers" reading.
- **IN-5, actor check.** `gate.py authorize` counts only as the command itself (not an `echo` argument, not in a comment), in a step with no `if:`, `continue-on-error` absent or the literal `false`, no `if`/`case`/loop/`&&`/`||`/`exit` before it, a `--actor` argument taken from the run (a `$` in it), and in the apply job before the apply or in a job it needs.
- **IN-7, remote reusable workflows.** `ci.remote-workflow-secrets`: a `uses: owner/repo/.github/workflows/x.yml@ref` job that gets `secrets:` (any value) or runs under `id-token: write` is an error when the workflow has a bot-reachable trigger, `pull_request_target` or `workflow_run`, or its ref is not a 40-character SHA; otherwise a warning. The doctor treats the same job as a deploy surface; the name heuristic stays as an extra signal.
- **IN-8, script injection.** `ci.script-injection` replaces the old field list: in `run:` and `github-script` any `${{ }}` with `github.event.*` (except `number`, `pull_request.number`, `issue.number`, `action`, `repository.*`), `inputs.*`, `github.head_ref`, `github.ref_name`, `github.ref`, `client_payload`, `toJSON(github.event)`; property names are case-insensitive and `github['event']` counts. `github.actor` is a warning. A comparison, negation or `contains()` yields true/false and is allowed; `&&` and `||` operands are judged one by one.
- **IN-9, pull-request code in a privileged job.** In `pull_request_target` and `workflow_run` jobs that hold secrets or `id-token`: `ci.pr-target-checkout-expression` (a computed `ref` or `repository` outside the allowlist), `ci.pr-code-fetch` (an archive fetched by curl, wget or `gh api` and unpacked), and `ci.artifact-from-pr-run` now covers `pull_request_target` and any action with `download-artifact` in its name.
- **IN-11.** New doctor check `deploy.environment-branch-policy` (warning): an Environment an apply job names has no deployment branch policy (or does not exist yet) in the recorded GitHub data. Best effort; skipped without data.
- **IN-12 (doc).** `.claude/templates/security/oidc/README.md` (new) and `docs/security/infra-ci.md`: the two apply trusts are alternatives; the `job_workflow_ref` one needs a repository-wide subject-claim customisation that changes every other trust.
- **IN-13.** `plan-readonly.policy.json`: a `Deny` on secret values and `kms:Decrypt` with `Resource: "*"`, and a `Deny` on `s3:GetObject` with `NotResource` the state bucket. No `aws:ResourceArn` condition.
- **IN-14.** `ci_lint._job_perm_for` is gone; `Ctx` gets `_job_perm`. `_perm` is `workflows.perm_level`.
- **IN-15.** `label-guard.yml` lower-cases the label, the sender and every approver, drops a leading `@`, and splits the approver list on commas and white space, as `gate.py` does; no globbing (`set -f`).
- **GT-12 and D1 item 5.** `levelcalc.cap_sandbox`: a FAIL on `sandbox.deny-paths` or `sandbox.registry-path` (package A's new row) caps the level at L3 when the sandbox is otherwise on and attested; the row is no longer left out of the "not proven" explanation. Unknown does not cap.
- **DEC-1.** `doctorlib/delivery.py`: `delivery.suggest-draft-pr`, an information row when `delivery` is `local` and the main-protection, code-owner, required-checks and bypass checks all pass. `levelcalc` imports it, so the doctor picks it up with no `doctor.py` edit. It never fails.
- **G4 docstring (D5).** `loopctl/gates/g4_mutation.py` says the gate runs in the driver and in CI.
- **Hostile input.** The new matching is linear in the text (`str.find` for `${{ }}`, no `[^\n]*` after a repeated word). The four existing deploy patterns that were quadratic in a line of repeated `curl`/`rsync`/`scp`/`vercel`/`docker buildx build` words now use `workflows._Near`; the old `_TF_SUBCMD` no longer lets a verb on the next line belong to `terraform`. (Second review, R-INFRA-3: the "flags between a tool and its verb" patterns were still exponential, see below.)

Second review (R-INFRA-1 to R-INFRA-6):

- **R-INFRA-1, fixed.** `ci_lint.lint_paths` reads the callers of each `on: workflow_call` workflow in the directory: the callee runs on the union of its callers' events (so the default checkout of a `pull_request` caller is PR code), and a callee with no `permissions:` gets `id-token` from a caller that grants it. A callee nobody in the set calls is read as if a pull request called it (when in doubt, error). `github.sha`, `github.ref` and `github['sha']` count as PR code on `pull_request` and `merge_group`. IN-9 no longer accepts a `steps.*` or `needs.*` output as a `ref` (`ci_lint._REF_OK_PRIV`; the apply-path allowlist `ci_rules._REF_OK` is unchanged), and `issue_comment` and `issues` are privileged triggers for IN-9.
- **R-INFRA-2, fixed.** Every gate command (`authorize`, `require-main-ref`, `require-run-approval`, `verify-hash`, `base-is-main`, `plan-digest`) is read with the conditions `authorize` had: the command itself (`echo gate.py ...` no longer counts), a step with no `if` key at all (a literal `if: false` is falsy once parsed, so the key is tested), `continue-on-error` absent or `false`, no `shell:` other than `bash` or `sh`; a workflow or job `defaults.run.shell` that is not `bash` or `sh` is `infra.gate-bypassable`. `sha256sum -c` and `ls-remote` are read as commands in plain steps. A main-ref check as a job `if:` must not contain `||` or a status function. The `plan-ok` label is read from job-level `if:` only.
- **R-INFRA-3, fixed.** `workflows.flags_re` replaces the ambiguous flag group (a flag name must start with a word character, a space-separated value may not start with `-` or be the tool's own name, so a token is a flag or a value and the run is linear, with no cap that a 9-flag command line could hide behind). Also made linear: the `gate.py` tail check (per line, from the first call), `(\S*)source_policy.py` (a bounded walk back from `str.find`), the `git fetch|pull|checkout ... pull/` patterns (`workflows._Near`), `github.event[...]` index matching, and the `terragrunt run` nesting (see Known gaps for the part still pending). The redact `url-credentials` regex is package B's.
- **R-INFRA-4, fixed.** `_yields_boolean` accepts a comparison, `!x` or one whole `contains()/startsWith()/endsWith()` call only as the top-level operator of an operand (strings, parentheses and brackets are tracked; `&&` and `||` split only at the top level). `${{ env.NAME }}` is flagged when `NAME` is an `env:` entry (workflow, job or step, followed through other entries) whose value interpolates untrusted text.
- **R-INFRA-5, fixed.** `deploy.environment-branch-policy` checks every Environment named by a job that applies or can obtain cloud credentials (`deploy.credentialed_jobs`), not only the apply jobs'.
- **R-INFRA-6, fixed.** `workflow_run` with `branches: [main]` is no longer main-only (a fork's branch can be called `main`): it is bot-pushable like any `workflow_run`; the label `workflow_run:main` is kept. `secrets[format(...)]` and any computed index count as a secret (`ci.secrets-in-pr-job`) and as a cloud credential; `secrets['AWS_...']` is a stored cloud key (before, only `secrets.AWS_...` was). `claude-review.yml` passes the review text through `kitlib.redact` and posts nothing if that cannot run. `plan-readonly.policy.json`: `lambda:Get*` is replaced by the named reads the provider needs (`lambda:GetFunction` stays and returns environment variables, documented); a `Deny` on `apigateway:GET` for `/apikeys` and `/apikeys/*`; the allow statement is renamed `ReadResourceConfiguration`.
- Tests: `tests/infra/test_ci_rules_review_fixes.py` (65, one positive and one negative per item plus bypass variants and a linear-time test), `tests/infra/test_templates_lint_clean.py` (every shipped workflow template: zero errors, warning set pinned), `tests/infra/test_label_guard_and_iam.py`, `tests/infra/test_delivery_suggestion.py`, new classes in `tests/doctor/test_deploy_surface.py` and `test_level_caps.py`. Two rows of `tests/infra/test_ci_rules.py` moved from warnings to errors.

## Upgrade impact

Stricter, by design. A project that already installed the infra workflows keeps passing (the shipped templates are lint-clean, and a test keeps them so). A project with its own workflows may now see: errors for a credentialed job on a push to any branch or a tag, for `docker://` images without a digest in a credentialed job, for a remote reusable workflow that gets secrets, for `${{ github.event.* }}` or `${{ inputs.* }}` in `run:`, for an Environment-only apply with no `require-run-approval`, and for `$VAR apply` in a credentialed job; and a doctor level cap where a credentialed job runs on a bot-pushable push. Those errors are unmet L3 "split CI" prerequisites. `env_reviewers_available` is stricter: reviewers on an Environment no apply job names no longer count.

Second review: more errors, as designed. A reusable workflow nobody in the directory calls and that holds a credential action now errors (it might be called from a pull request); `${{ env.X }}` where `X` comes from event text errors; an infra workflow whose gate step has an `if:`, a custom `shell:` or only echoes the gate command errors; `workflow_run: branches: [main]` deploys count as bot-pushable in the doctor (cap L1 unless gated). A plan role that manages `aws_api_gateway_api_key` needs the new API key deny removed on purpose. Round 3: a deploy that a flag value with blanks (`--context ${{ matrix.ctx }}`, `-c a="x y"`) or a package runner (`npx aws-cdk@2 deploy`) used to hide is now found, by the lint and the doctor alike, so a workflow that passed only because of that gets the `infra.apply-ungated` family of errors, and the doctor counts it as a deploy surface. The doctor no longer reads `x-cdk deploy` or `foo.cdk deploy` as a deploy.

## Decisions made

- **Findings.** IN-1 fixed; IN-2 fixed; IN-3 fixed; IN-4 fixed (lint and doctor); IN-5 fixed; IN-6 fixed; IN-7 fixed; IN-8 fixed; IN-9 fixed; IN-10 not mine (package A); IN-11 fixed as a warning; IN-12 documented; IN-13 fixed; IN-14 fixed; IN-15 fixed; GT-12 fixed; D1 item 5 fixed; DEC-1 carry-over built.
- **A new rule for IN-1 instead of widening `ci.secrets-in-pr-job`.** The decision said "R2 ... a credentialed job needs a gate on these triggers". Widening R2 to a push would also change the checkout test every other rule uses. `ci.credentials-on-bot-push` is separate, exempts a job with a static `environment:` (the human gate for a non-apply job; for an apply the Environment rules above apply), and does not exempt `environment: ${{ ... }}`.
- **Deviation from D9 item 8 (`download-artifact`).** The official `actions/download-artifact` under `pull_request_target` is flagged only when it names another run (`run-id`, `repository` or `github-token`); under `workflow_run` it is flagged as before. Reason: the shipped `infra-plan.yml` plan job (OIDC, `pull_request_target`) downloads the same run's artifact and checks its hash first, and the decision's "no shipped template fails" would not hold otherwise. Any other action with `download-artifact` in its name is flagged.
- **`--actor` must come from the run (extra to D9 item 5).** `gate.py authorize --actor alice` passes for ever. Cheap, and the shipped templates already pass `"$ACTOR"`.
- **`TF=terraform` is followed (extra to D9 item 2).** Resolving a same-script assignment turns `$TF apply` into a normal apply (all the apply rules fire) instead of only an indirect-command error. At most 16 assignments per script, so a hostile script cannot make it expensive.
- **Docker image tags are read through (extra).** `docker run hashicorp/terraform:1.9 apply` is an apply.
- **Delivery check without a `doctor.py` edit.** `levelcalc.py` (mine) imports `doctorlib/delivery.py`, which registers the check. Group `config`.
- **G4 docstring.** The decisions file gives it to package C with the spec; this task's brief gave the docstring to D. Only the docstring changed here; the spec row (`.claude/spec/loopctl-gates.md`) is under pointers.
- **Not done: attestation exemption for IN-7.** The decision said "unless the repo attests it". The lint has no attestation input; the doctor's `deploy_triggers` attestation is where a person accepts such a workflow.
- **Known gaps.** A command inside a script file, `eval`, `sh -c "$CMD"` or `make` target is outside the lint (the doctor follows one level of scripts; `.github/**` is a CODEOWNERS path). A value laundered through `steps.*.outputs` or `needs.*.outputs` into `run:` is not seen as untrusted. A static `environment:` on a non-apply credentialed job is taken as the human gate without checking reviewers (the doctor's `gh.environments` row reports a repo where none has reviewers). `ci.credentials-on-bot-push` does not look at `issue_comment`, `release` and similar events. The docker image list is names, not behaviour. A required `--actor` with a `$` is a shape check, not proof the variable holds the actor.

- **Round 3: the blanks of a span are made one word in a copy, not in place.** Replacing them in place would hide `sh -c "kubectl apply -f x"` and `$(terraform apply)` from every rule; a copy added behind a separator line (`\x00`, which no pattern matches across) only adds matches. Only lines that hold a span with a blank are copied, and the copies are kept apart so a tool at the end of one line and a verb at the start of another do not meet. Cost: the text is up to four times longer (three levels and the original); the gate rules read the same text, and read the original lines first.
- **Round 3, `foo.cdk` and `x-cdk`: neither is a call, in the doctor or the lint.** The reviewer's suggestion was to drop `-` from the lint's lookbehind; that makes `x-cdk deploy` and `my-cdk destroy` an `infra.apply-ungated` error for a file name or a script that merely ends in the tool's name, which is a false positive an honest repository would have to work around. The doctor's `\b` was the looser rule and read both as a deploy; it now has the lint's rule (`workflows.PROG_BEHIND`), and the one thing a `/` in front used to give the doctor (a path through a variable, `${DIR}/cdk deploy`) is read as the bare tool by `normalize_shell` instead. The packages that really are the tool (`aws-cdk`) are read as it by name, not by loosening the rule.
- **Round 3: the package aliases apply anywhere in a script, not only after `npx` or `dlx`.** There are many runners (`npx`, `pnpm dlx`, `yarn dlx`, `bunx`, `npm exec`, `pipx run`, `uvx`) and their flags (`-y`, `--package`, `--`) come between the runner and the package. The price is that a script that only installs `aws-cdk` reads as an infrastructure script (its rules still fire only on an apply or a credential).
- **Round 3 (superseded by round 4, D6): the span pass is bounded by delimiters, not by text size.** It was 60,000 per script, shared by all levels, then the rest read as written; it is now 100,000 and an unreadable script (see "Fourth review"). Fail-closed here means nothing is swallowed and nothing is lost (the original text is always matched); an attacker who pads a script with sixty thousand delimiters to hide one `${{ }}` flag value can hide the same command in a script file, which is outside the lint already.
- **Second review, still open.** (1) A value laundered through `steps.*.outputs`, `needs.*.outputs` or `$GITHUB_ENV` into `run:` is still not seen as untrusted (R-INFRA-4); `actions/cache/restore` keyed by a PR value under `workflow_run` is not flagged. (2) A gate command with neutered arguments (`--approvers "*"`) passes the shape check. (3) A callee is judged only when its callers are in the linted directory; one called from another repository is read as a pull-request caller. (4) The doctor checks the branch policy of a credentialed job's static Environment only; a dynamic one is the lint's. (5) `lambda:GetFunction` cannot be dropped from the plan role (the provider needs it), so function environment values stay readable by it. (6) A dash-led word that is not flag-shaped (other than terragrunt's `--`) ends the flag run. (7) A flag value that is a process substitution (`<(echo a b)`) is not read as one word; the span pass reads quotes, `$(...)`, `${...}`, backticks, `${{ }}` and escaped blanks. (8) A quoted command inside a quoted command is read to three levels, and the span pass looks at 100,000 delimiters per script at most (beyond that the script is unreadable, see "Fourth review"); a quoted command more than three levels deep is read as written. An opener with no closer (a syntax error for GitHub and the shell) is an ordinary character, so a value after it that needs the other end to be one word is not joined. (9) `sst`, `amplify`, `fly`, `wrangler`, `netlify`, `firebase`, `vercel` and the publish commands are deploys for the doctor and not infrastructure applies for the lint (a difference of scope, not of spelling); `npx sst@latest deploy` is `sst deploy` for the doctor only. (10) The package names `aws-cdk`, `cdktf-cli`, `aws-sam-cli`, `firebase-tools` and `netlify-cli` read as their tool anywhere in a script, so a workflow that only installs one (`npm i -g aws-cdk`) is now treated as an infrastructure workflow (its rules still fire only on an apply or a credential).

- **Second review, fixed.** The flag run between a program and its verb (`flags_re`, shared by the doctor and the lint) no longer lets a value that begins with the program's name hide the verb (`cdk --app cdk.out deploy`, `kubectl --kubeconfig kubectl/cfg apply`, `terragrunt run --all --working-dir terragrunt/live apply` were missed), and stays linear: a run stops only in front of a token that is the program's name, by each module's own rule for where a call may start (`cdk --a=cdk …` and `-a x/cdk …` were quadratic). Terragrunt's `run`, `run-all`, `stack` and `--` are words of the run, never a value, so `run -- apply`, `run --all --working-dir run apply` and `stack run apply` match. Flag values may be quoted with spaces. `id-token: write` passes down a chain of reusable workflows that set no permissions (`ci.oidc-with-pr-code` missed a top → mid → callee chain), and callers are resolved by passes over the call graph (was exponential in the chain length). The plan role's `NeverReadApiKeyValues` also denies `/usageplans/*/keys` (GetUsagePlanKeys returns key values). `test_templates` checks the plan role against an allowlist of read verbs.
- **Second review, round 3 (D1, D2, D3), fixed.** (D1) A flag value with blanks hid the verb: `terraform -chdir=${{ matrix.dir }} apply`, `kubectl --context ${{ matrix.ctx }} apply`, `cdk --profile ${{ matrix.p }} deploy`, `helm --kube-context ${{ matrix.c }} upgrade`, `pulumi --stack ${{ matrix.s }} up`, `terragrunt --working-dir ${{ inputs.dir }} apply` and `kubectl --namespace $(echo x y) apply` gave no `infra.apply-ungated`. `workflows.normalize_shell` (so the lint's `_norm_run` and the doctor's `deploy_labels` alike) now finds the spans that hold blanks in one pass with a stack (`_blank_spans`: quotes, `$(...)`, `${...}`, backticks, `${{ ... }}` with strings that hold `}}`, escaped blanks, nesting, comments skipped) and adds behind a separator line a copy of each line that holds one, with the blanks inside the span made one word. The original text stays, so `sh -c "kubectl apply -f x"` and `$(terraform apply)` are read as before; a quoted command is read again for its own values, to three levels (`ssh host "kubectl --context ${{ a b }} apply"`, `bash -c 'cdk -c "a b" deploy'`). `ci_rules._tf_calls` lists a call once (the copy repeats the lines). (D2) `npx aws-cdk deploy`, `npx aws-cdk@2 deploy --all`, `npx cdk@2 deploy` and `pnpm dlx aws-cdk deploy` are `cdk deploy` for the lint and the doctor alike: `normalize_shell` reads `aws-cdk`, `cdktf-cli`, `aws-sam-cli`, `firebase-tools` and `netlify-cli` as their tool and drops a version or dist-tag (`@2`, `@^2.1`, `@latest`) after a tool name or such a package; and the doctor and the lint now share one start rule, `workflows.PROG_BEHIND` (`(?<![\w./-])`): `x-cdk deploy` and `foo.cdk deploy` are a call in neither (the doctor used to read both). A path after `${DIR}`, `"$DIR"` or `$(pwd)` (`${DIR}/cdk deploy`) is read as the bare tool, so the doctor does not lose it. (D3) `cdk -c a="x y" deploy`, `helm --set a="b c" upgrade`, `cdk -a'x y' deploy`, `kubectl -n my\ ns apply`, a quoted value of any length (the 200 character limit of the flag pattern only applies to the original text now; the copy has no blank to stop at) and a value over several lines match. `flags_re` accepts a quoted value attached to a flag (`-a'x y'`) when its quote is closed, so `echo "cdk -c" deploy` is not a flag with a value. An empty quote pair is dropped only when its first quote is not escaped (`"a=\"b c\""`).

### Fourth review (round 4: D1 to D6 and the structural wrapper)

Principle (from the round-4 decision): the boundary is the human apply gate (H4); the lint and the doctor's scan are defence in depth. Fixed: regressions, crashes, hangs, and cheap fail-closed changes. No new regex families.

**Fixed**

- **Structural, fail closed.** `ci_lint.lint_text` returns one `ci.unreadable` error for a file on which anything goes wrong while it is read (an exception, `RecursionError`, `MemoryError`, `workflows.ScanLimit`); `lint_paths` does the same for the call graph of reusable workflows (every callee is then judged as if a pull request called it) and no longer lets the parser's own failure escape. The doctor's `deploy.classify_workflow` returns, for a file its reader cannot read, a row that deploys on `push:branches` with an `unreadable:` label (so the B5 cap applies); `deploy._jobs_with_environment` counts a job it cannot read as an apply; `workflows.deploy_labels` returns `UNREADABLE_LABEL` for a script past the limit. Tests: `test_ci_rules_round4.UnreadableIsNeverClean` (7), `test_deploy_surface.UnreadableWorkflowsAreDeploys` (4).
- **D1, comments.** `workflows.strip_comments` (used by the lint's `_norm_run`) replaces the `(?:^|\s)#` regex with a per-line tokenizer (`_comment_at`) that knows `'...'`, `$'...'` (with `\'`), `"..."`, `$(...)`, `${...}` and `${{ ... }}`, backticks and an escaped blank. A `#` inside a quote, an expression or `a\ #b` is not a comment (`cdk -c "a #b" deploy`, `terraform -chdir="a #b" apply`, `kubectl --context "a #b" apply`, `cdk -c ${{ format('a #{0}', x) }} deploy`, `cdk -c $(echo a #b) deploy` were all missed by the lint). A line whose quoting is unbalanced or unclear, or has more than 20,000 delimiters, keeps its `#`: nothing is stripped. Tests: `ShellTokenizer.test_a_hash_inside_a_quote_or_an_expression_is_not_a_comment`, `test_a_real_comment_is_cut`, `test_an_unbalanced_line_keeps_everything`, `test_the_reviewers_hash_inputs_are_applies`, `test_a_commented_out_deploy_is_still_not_one`.
- **D2, span pairing.** The span pass pairs quotes within a line (a quote with no closer on its line is an ordinary character there), and separately over the whole piece for values that run over several lines; the two sets are kept apart so one cannot join the other. A stray apostrophe in a heredoc body or in `echo don't` no longer hides the values after it (`cat <<'EOF'` / `don't forget` / `EOF` / `cdk -c a='x y' deploy`, and the `say "hi`, backtick, `$( $( $(`, `${{ ${{`, `' ' '` variants). `$'...'` is read with `\'` (`terraform -var $'a\'b c' apply`, `cdk -c $'a\'b c' deploy`). A `#` inside `$(...)` is no longer a comment there. Tests: `ShellTokenizer.test_a_heredoc_with_an_apostrophe_does_not_hide_what_follows`, `test_a_stray_apostrophe_on_another_line_does_not_pair_with_a_real_quote`, `test_ansi_c_strings_with_an_escaped_quote_are_one_word`, `test_a_value_over_several_lines_is_still_one_word`, `test_a_pad_of_quotes_does_not_hide_the_tail`.
- **D3, bare variable words.** `flags_re` accepts a word that starts with `$` or `"$` (`$FLAGS`, `${FLAGS}`, `"$@"`, `"${ARGS[@]}"`, `${{ inputs.flags }}` after the blanks are made one word) as a stand-in for flags; it is never the value of the flag before it, so a token still has one parse. The lint's `_TF_SUBCMD` now reads the flags before the verb with the same grammar (it allowed only `-chdir=`; any flag, a variable word or a quoted value now does, as the doctor always did). Tests: `BareVariablesAsFlags` (5).
- **D4, `aws`, `gcloud`, `az`.** The service name is read after the flags grammar: `aws --region x cloudformation deploy` (lint and doctor), `aws --region x ecs update-service`, `gcloud --project p run deploy`, `az --subscription s webapp deploy` (doctor). Tests: `GlobalFlagsOfCloudClis` (4).
- **D5, quotes inside words; a variable in command position.** A quoted run of word characters inside a word is dropped (`terra'form' apply`, `ap"ply"`, `'t'e'r'r'a'form'`); `T="terraform"` then `"$T" apply` is the tool (the unquote pass runs again after assignments are substituted); a variable in command position followed by `apply|destroy|deploy` that is not an assignment from the same script is the doctor label `deploy through a variable` (deploy-capable); the lint already reports it as `infra.apply-indirect`. Tests: `QuotesInsideWordsAndVariableCommands` (5).
- **D6, the delimiter budget and NUL.** More than 100,000 delimiters per script (all variants and levels share the count) raises `workflows.ScanLimit` instead of reading the rest as written; the callers above turn it into a finding. A NUL is a separator: the text is read once with each NUL as a blank and once with it dropped (bash drops it), behind the separator line. `CRLF` after a backslash joins lines. Tests: `DelimiterLimitAndNul` (5), `SpanPass.test_the_delimiter_limit_makes_a_long_text_unreadable_not_clean`, `HostileInputUnderTwoSeconds` (200 KB: each of four hostile shapes through the whole lint, the doctor's labels and the raw-text scan, under 2 s; the comment cutter alone under 2 s).
- **Also.** `_TF_SUBCMD` and the comment and span passes are cached per script (`_norm_run` has an `lru_cache`). `npx aws-cdk@v2` drops the `v`. The in-repo corpus (every workflow under `.claude/templates`, `.github/workflows`, `examples`, `docs`: 16 files) gives identical lint findings and doctor labels before and after this round (no true positive to list there).

**Still open (known gaps, as text)**

- Not read: process substitution `<( )` as a flag value; a `case` pattern's `)` inside `$( )`; `${T}form` built from a variable; `opentofu`, `terraform.exe`, `cdk.js`, `npx @aws-cdk/cli`; `flux`, `argocd`, `packer`, `ansible` (python), `gh workflow run`, `gh api .../dispatches`, `curl` to a dispatch URL; `aws cloudformation create-change-set` and `package` (they do not apply).
- The lint does not treat `aws ecs|lambda|s3`, `gcloud` and `az` as infrastructure applies (the doctor does); that is a difference of scope. `terraform -var x apply` is not valid terraform; both tools read it as an apply.
- A command in a script file, an alias, `eval`, a `make` target, a value passed through step outputs: outside both, as before. Any new variant of a pattern class found after this round.
- Only the 16 in-repo workflows were used as the honest corpus; workflows from other repositories were not compared.

**Decisions made**

- **Unreadable is a finding, not an exception to the caller.** `lint_text` and `classify_workflow` catch everything (including `RecursionError`); `normalize_shell` itself raises `ScanLimit` (a reviewer's probe that calls it directly sees the exception), while `deploy_labels` returns the unreadable label. The lint's error is `ci.unreadable`; the doctor's is a deploy on a bot-pushable trigger, so the level cap applies.
- **Unclear means keep more.** The comment cutter strips nothing from a line it cannot balance; the span pass reads an unclosed quote as an ordinary character and uses both the per-line and the several-lines pairing. Both only ever add text to the matched text.
- **Heredocs are not parsed.** The per-line pairing makes a heredoc body harmless without finding its end marker (a fake marker could otherwise hide a real command). Comment cutting applies to heredoc body lines like any other line.
- **Terraform flags before the verb.** The lint now reads them like the doctor (a disagreement the reviewer listed). `terraform -var x apply` is invalid terraform, so this only widens what is flagged.
- **`"$T" apply` in the doctor.** A new deploy label rather than a silent pass; verbs `apply`, `destroy`, `deploy` only (not `up`, which `docker compose` uses).
- **Docs.** `docs/security/README.md` (the paragraph after the five elements), `docs/security/infra-ci.md` (top of "What it does not cover") and `docs/security/deploy-surface.md` ("Limits") say these readers are heuristic and a clean result is not evidence of safety; the control that holds is the environment-protected apply.

### Fifth review (round 5: D1 to D6, the last round)

Scope (round-4 decision): regressions, a way past a round-4 fix, a hang. Fixed all six; the same fix also covered the lint's twin of D1.

**Fixed** (tests in `tests/infra/test_ci_rules_round5.py`, 29 tests, about 2.5 s)

- **D1, hang.** The variable-command regex (`"$T" apply`) is now built by `workflows.var_command_re`: `NAME=value ` assignments are at most eight, each value at most 200 characters and none runs over `;`, `&`, `|` or a newline; flags and variable words after the variable are at most sixteen, on one line, none running over a separator. `;A=x` x 50,000 took 44 s and `;$A -x` x 33,333 took 33 s; both are 0.01 s now, and `classify_workflow` on a 100 KB workflow is 0.1 s (was 10.9 s). The lint's `ci_rules._INDIRECT_RE` had the same shape (44 s, 33 s and 24 s on `;A=x`, `;$A -x`, `;"$A" -x` in a job that runs an infra tool; the reviewer's probes did not reach it); it now uses the same text, so the doctor and the lint share one regex. Tests: `VariableCommandIsBounded` (6: every regex alone under 0.2 s at 200 KB on 20 shapes; the reviewer's two inputs through the whole doctor and lint; `classify_workflow` at 100 KB; an infra job with a hostile script).
- **D2, stray quote.** `_piece_spans` now runs the pass over several lines once from the top and again from the line after each of the first six lines with an odd number of `'`, `"` or `` ` `` (`_fresh_starts`). For one kind of quote there are only two ways to pair a run of quote characters, and a restart after the first odd line gives the other one, however many stray lines come first. Each pass is its own level (spans of two passes are never merged, so a wrong pairing only adds a copy of some lines). Tests: `StrayQuoteBeforeMultiLineValue` (8): the reviewer's three inputs, 1 to 200 stray lines, single and double quotes, terraform and kubectl, a read-only neighbour, the bound, 200 KB hostile shapes under 2 s.
- **D3, comment continuation.** `ci_rules._norm_run` cuts comments per physical line first and joins continuations after. `echo a # c \` then `terraform apply` is an apply. A real continuation is still joined. Tests: `CommentEndsAtItsLine` (4).
- **D4, `$'..'`.** `_UNQUOTE_RE` takes an optional `$` in front of the quote: `$'terraform' apply`, `terraform $'apply'`, `$"terraform" apply` (lint and doctor). Tests: `AnsiQuotedWords` (3).
- **D5, variable command forms.** `"$T" -var-file x.tfvars apply`, `"$T" -chdir infra apply`, `sudo "$T" apply`, `env X=1 "$T" apply`, `"${CMD[@]}" apply` are the label `deploy through a variable` and, in an infra job, `infra.apply-indirect`. Prefixes: `sudo`, `exec`, `command`, `nohup`, `time`, `env`, up to three, each with assignments. A flag takes one value that is neither a flag nor a variable, so a token has one parse. Tests: `VariableCommandFlagsPrefixesAndArrays` (5).
- **D6, regression.** The verb ends with `(?![\w-])`: `"$CMD" deploy-docs` is no deploy (doctor and lint). Tests: `VariableCommandVerbEnd` (3).

**Decisions made**

- **One regex text for the doctor and the lint** (`workflows.var_command_re`, exported with `VAR_WORD`). The lint's start rule also takes `else`, its command word also takes `$(...)` and backticks, and its verbs also `up`; everything else is shared, so the bounds hold in both.
- **The lint's `up` also ends at a word boundary that is not a hyphen** (`$CMD up-to-date` was a hit).
- **Restarts are bounded at six, not one per line.** A pass per line is quadratic; the parity argument says the first odd line is enough for one kind of quote, and six cover the mixes of kinds that matter. A stray on the value's own line is not helped by any line-level restart (known gap below).
- **The extra passes share the delimiter budget** and so fail closed. Cost: a script with more than about 10,000 delimiters and an odd line near its top may now be `ci.unreadable` (an error) where it was read before. No honest workflow in the corpus is near that, and a script that long belongs in a file.
- **No `${{ }}` or path command word, no flag-run limit above sixteen.** See below.

**Still open (known gaps, as text; not fixed on purpose)**

- A stray quote on the same line as the value (`echo don't; cdk -c 'a` newline `b' deploy`), or strays of two kinds interleaved with the value, can still pair wrongly.
- `${{ matrix.tool }} apply`, `"$DIR/$T" apply`, `eval "$T apply"` and `sh -c "$T apply"` are not read as a variable command; neither are more than sixteen flags before the verb, or a `sudo` option (`sudo -E "$T" apply`).
- `t'e'r'r'a'f'o'r'm' apply` written with double quotes, and a flag value that is a backtick pair or a process substitution standing alone (`cdk $(echo -c a=b) deploy` is read; `` cdk `echo -c a=b` deploy `` is not). The quote-in-word pass runs three times.
- `aws`, `gcloud` and `az` verbs after flags are the doctor's only; the lint has no rule for them (scope, as before).
- Checked at round close: the in-repo corpus (48 workflows: every tracked `.yml` and `.yaml` file and the fenced YAML workflows in `docs/`, `examples/` and `.claude/templates`) gives identical lint findings and doctor labels before and after; the honest-script table of the reviewer (62 rows) differs only in `"$CMD" deploy-docs`, which is now quiet.
