# 4c-driver: the serial loopctl driver (`runner: driver`, OPT-IN), child launch, liveness and the compact hook

## Changes

- `.claude/scripts/loopctl/driver.py`: `run(ctx, loop, run_record, as_json) -> int`, the seam 4a defined. For each eligible item it runs the pipeline `begin -> designing -> design_review -> [stubbing] -> building -> verifying -> reviewing -> merged | awaiting_human`, launching a child `claude -p` session for every piece of judgement work (one per engineer role, then `code-reviewer`, and `security-reviewer` per `security_review`), running the gates through 4a's runner, and writing state by compare-and-swap. A step back is `Loop.fail` and the driver obeys its answer (retry with the backoff slept interruptibly, discard to attempt n+1, park, hard stop); a park or hard stop ends the run (exit 1). Checkpoints follow `autonomy` (per-feature, per-milestone, and always after an infra item); a human-gated, infra or non-`local`-delivery item stops at `awaiting_human` and merges only after `loopctl approve item`, and only if its branch has not moved since. Recovery after a crash is the same code path as a normal start (`reconcile` fed the in-flight items). Spec: `.claude/spec/loopctl-driver.md`.
- `.claude/scripts/loopctl/launch.py`: the one module that starts `claude`. Fixed argv (`claude -p --agent ... --agents ... --settings ... --allowedTools ... --permission-mode dontAsk --max-budget-usd <remaining> --output-format json --session-id <uuid>`), the prompt on stdin from a file, a scrubbed environment (allowlist; no `AWS_*`, `GH_*`, `GITHUB_*`, `SSH_AUTH_SOCK`, `CLAUDECODE`; a plan's `requiresEnv` and `verify_env_allow` pass unless they name a credential family), the child profile built from Phase 2's templates and **validated before every launch** (`Workflow` or `claude` allowed, a blanket allow, a non-`dontAsk` mode, the sandbox off, missing kit hooks: refused), the agent definition read from the base sha, refusal inside a Claude Code session (the test harness may opt in only with the fake binary), the version range check (report 14.2), a process group per child with SIGTERM then SIGKILL, a sweep of the group after a normal exit, `children/<session>.json` records and `reap_orphans` for a driver that was SIGKILLed.
- `.claude/scripts/loopctl/heartbeat.py`: the driver's side of the lock (a timed heartbeat; HALT, a lost lock and a signal end a running child within one poll), the child's last sign of life (its telemetry stream, subagent streams, output) for the stall rule, and the canary check.
- `.claude/scripts/loopctl/compact_hook.py`: the SessionStart `compact` hook (report 10.6): re-reads the state and returns the current item, stage, attempt, last failure, counters, what waits on a human, the brief and report paths (a driver child) or the next loopctl command (the conductor), the canary line, at most 10,000 characters. Prints nothing for a session that is not part of a run. Wired through `hooks.manifest.json` (`session-start-compact`), so `settings.v2.json` and the headless and critic templates carry it; the driver also adds it to a profile that lacks it.
- Additions to 4a modules, each because the driver contract had a real gap: `Loop.record_gates` (one compare-and-swap per gate round instead of one per gate), a parsed-commit cache in `StateStore` (a commit id names its content; copies are handed out), `RunLock.takeover` and `lock.owner_dead` with their use in `startrun` (the lock of a driver whose pid is dead on this host is taken over at once, whatever its heartbeat says: without it a crashed driver blocks `loopctl run` for `lock_stale_min`), `startrun.preflight` reporting it.
- `tests/helpers/fake_claude.py`: scenarios for the driver (`by_role`, `nonce_dir` and `events_dir` emulating the SessionStart canary and the telemetry hook, `tool_events`, `canary: false`, `spawn_sleeper`, `hook`, `pid_log`, the `budget_exceeded`, `max_turns`, `rate_limited` and `error` behaviours, an optional cost on `overloaded`) and the marker the driver looks for. No existing scenario changed.
- Tests: `tests/loopctl/fault_injection/` (155 tests, 18 modules; each module is under ~8 s alone, about 55 CPU-seconds in all). Two 4a test modules follow the driver existing: `tests/loopctl/test_run.py` (the "driver not installed" case now hides the module) and `tests/loopctl/test_cli.py` (the source rules let `launch.py` start a process and name the binary, and know `signal`, `uuid`, `session_start`).

## Upgrade impact

None for anyone who does not opt in: `runner` stays `sequential`, so `loopctl run` still prints the hand-off. After the guards are activated (IMP-13) a `compact` SessionStart runs `compact_hook.py` in every session; it prints nothing unless the session belongs to a loop run. `python3 .claude/scripts/guards/wiring.py --write` regenerates `.claude/settings.v2.json` and the settings templates after merging (the manifest gained one entry). A project that opts in sets `runner: driver` and a `run_budget_usd` in a committed loop.config (both H6) and starts `loopctl run` from a plain terminal; inside a Claude Code session the driver refuses.

## New config keys

None. The driver reads keys registered by others: `runner`, `run_budget_usd`, `item_budget_usd`, `day_budget_usd`, `dispatch_timeout_min`, `max_platform_retries`, `max_transient_retries`, `platform_backoff_base_s`, `lock_stale_min`, `max_retries_per_item`, `max_consecutive_failures`, `autonomy`, `autonomy_level`, `security_review`, `model_profile`, `delivery`, `always_human_paths`, `roster`, `verify_*`, `verify_env_allow`, `gates.*`. Internal limits that are not keys: the wall-clock limit of one child (six stall limits), the poll interval, the canary wait (90 s), the SIGTERM grace (10 s).

## Decisions made

- **The plan item is the design.** In driver mode there is no architect or design-critic child: H1 and H2 already approved the item's intent, criteria and footprint, and slicing (report 11.5) gave it its size. `designing -> design_review -> building` advance without a child and the history says why. The design-critic role stays available to `launch.py` (it is a critic profile) for a later phase that wants a design stage. `max_design_rounds` is therefore unused by the driver.
- **Stages and roles.** Engineers come from `estimate.engineers` (else `<domain>-engineer` for each footprint domain on the roster), ordered infra, database, backend, app, admin-app. The driver writes the briefs from the plan item (`docs/features/<slug>/briefs/<domain>.md`) and commits a WIP commit after each engineer, so each review has an exact range (D-4). `acceptance-author` is launched only when `gates.g2` is not off, `g2` is installed and its agent definition exists (4b); until 4b merges the stage is skipped.
- **Done is a valid report and a state transition, never "the process returned"** (report 11.3). Report checks are `report.read_report` (4a). A reviewer returns its verdict in its final message (the reviewers have no Write tool); the driver saves it under `docs/features/<slug>/reviews/<role>-r<N>.md` and records the verdicts as a `reviews` gate result (`evidence.review`), so `status --matrix` and the audit block see them.
- **Gate phases are fixed in the driver**: `g0` at the start of an item, `g2` after the stubs, `g5 g1 g3 g6 g9 g11` in verifying (a blocking `g5` ends the round: a test-integrity hit makes the rest pointless; reason `reward_hack`, which discards), `g7` after the reviews. `evidence` is CI's. A gate that is not installed is skipped and logged; an `off` gate is not recorded. A transition's `REQUIRED_FOR` gates that have not passed for the current head are run before it. A round records one failure, the worst class winning (env, platform, transient, item). A gate result's own `findings[0].reason` is honoured only if it is valid for its class (a failure cannot be relabelled).
- **Gate base sha.** A gate receives `base_sha` = the item's branch point (the integration tip when it began), so its diff is the item's own; `cfg` and the plan are the run's start anchor for the whole run (CO-11). An item that edits `.claude/loop.config.md` or an agent file changes neither its own budget, gates nor reviewers; the edit is a diff for a human and G5.
- **Unknown cost parks, including for a child that printed nothing.** A killed (stall, HALT) or crashed child has no result and so no cost; the ledger records unknown and the run parks after the failure is recorded (class, counter, backoff are kept). A human runs `loopctl approve cost` (and `approve unblock ... --choice reset`) and starts again. This is IMP-25 read strictly; the alternative (charge the launch allowance, or charge nothing) either parks every crash with a wrong reason or lets killed children spend uncounted. The consequence for unattended runs (Phase 7): a stall parks and notifies; a measured estimate from the session transcript would remove that.
- **`run_budget_usd` is per `loopctl run`** (the 4a ledger keys the run ceiling by run id); `day_budget_usd` spans runs. A restart after `approve cost` therefore starts a fresh run budget.
- **A child failure the CLI itself caused is `platform`**: a signal, an exit other than 0 or 1, output that is not JSON, an error nobody can read (`cli_crash`). `classify_exit` defaults an unreadable exit to `item`; the driver overrides that, because the item is not blamed for what the CLI did. Nothing a child wrote is stored in `lastFailure.detail`, and a platform failure re-runs the same prompt (no REWORK), so a child's text cannot travel through the state into another child's prompt.
- **A wall-clock limit per child** (six stall limits, two hours by default) because liveness alone cannot end a child that keeps calling tools and never finishes; its budget does only if it spends. Reason `timeout`, class `transient`.
- **Lock takeover** is allowed only for a lock whose `driverPid` is dead on this host (a conductor's lock, another host, a live pid and an unreadable lock keep needing a human). It does not wait for `lock_stale_min`: a dead pid cannot stamp a heartbeat.
- **A competing write that makes the driver's step meaningless stops the driver** (exit 3) and the other write stands; a driver that no longer holds the lock writes nothing and leaves the worktree alone.
- **Exit codes**: 0 the plan is complete or the run stopped on purpose for a human (a checkpoint, an item awaiting approval, a human's `stop`); 1 something is parked or stopped (hard stop, budget, interrupt); 2 internal error; 3 refused (HALT, lost lock, nesting, version, profile, a checkpoint nobody answered).
- **Checkpoints**: `per-feature` pauses after every merge, `per-milestone` at a milestone boundary (not after the last item), an infra item always; `unattended` never (it is evidence-gated, so it cannot be on yet). The pause is `header.parked = checkpoint`; the next start needs `approve checkpoint`, consumed once.
- **No push, no PR.** `delivery: push-branch` or `draft-pr` ends an item at `awaiting_human` with a message; the human pushes (`pr_prepare` prints the commands) and `reconcile` records the merge. The L2 push by the driver process is a later phase (Phase 7).
- **Fork-mode variables** (`CLAUDE_CODE_FORK_SUBAGENT=0`, `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`) go into every child's settings `env`; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` is passed through when set. The doctor's `fork.env` check (probe-assumptions V18, *planned*) is not in the Phase 1 doctor; a conductor pointer.
- **The doctor's effective level** is computed once per run for `GateContext.level` and not against the fake binary.
- **Test seams that are not for real runs**: `KIT_FAKE_CLAUDE_HARNESS=1` lets the driver run with `CLAUDECODE` set only if `KIT_CLAUDE_BIN` is a file carrying the fake's marker in its first 4 KiB; `KIT_DRIVER_TEST_TIMING` shortens waits only for the fake.
- **The compact hook prints nothing for a session that is not part of a run** because it is wired for every compaction.

Adversarial attempts against the driver, each with a test (`tests/loopctl/fault_injection/`):

- plan text with shell metacharacters, newlines, a fake `## Out of Scope` heading, ANSI and bidi controls: never on a command line, cleaned in the brief, cannot open a section (`test_adversarial_driver.Plan`)
- an engineer that edits the agent file of the reviewer that will judge it, the loop.config that holds its budget, the plan: the base sha's version is used (`test_adversarial_driver.Plan`, `test_flow_happy`)
- role names that become paths or flags: dropped, refused (`test_adversarial_driver.Plan`, `test_launch_unit.AgentDefinition`)
- hostile costs: negative, string, null, infinite, a renamed field: unknown, park (`test_adversarial_driver.Costs`, `test_faults_cost`)
- a child that never ends but keeps calling tools; one that ignores SIGTERM; one that leaks a dev server into its group; a recycled pid recorded as an orphan; records pointing at pid 1 (`test_adversarial_driver.Child`, `test_children`)
- a hostile or tampered profile (Workflow allow, claude allow, blanket allow, bypass mode, hooks removed, sandbox off) and credentials in the shell or the plan's `requiresEnv` (`test_launch_unit.Profile`, `.Environment`, `test_faults_process`)
- a report that is a symlink, has its trailer in a code fence, points outside `docs/features`, or claims another status (`test_flow_statuses`, `test_adversarial_driver.Child`)
- a verdict quoted from the reviewer's own template (`test_driver_helpers.Verdicts`)
- a lock replaced mid-run, a lock of a live driver, another host, a conductor, a corrupt file (`test_faults_lock`)
- a human who approves item A and then a commit lands on A's branch (`test_flow_human`)
- a competing abort, a stream of competing writes, a lost race on the merge record (`test_faults_state.Cas`, `test_faults_crash`)
- found and fixed on the way: a platform backoff recorded before a park outliving the unblock (the item could not begin: the driver now waits it out); child output reaching a later prompt through `lastFailure.detail` (state keeps only structured facts now); a platform failure being re-run with a REWORK prompt; a `requiresEnv` variable present in the driver's shell but missing in the child's; a registered session left behind when a launch line was refused; a worktree left on an item branch after a refusal or a stop; an item-branch merge whose record lost a race (recovered from the trailer in the same run).
