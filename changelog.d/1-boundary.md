# 1-boundary: the real boundary (doctor, ci_lint, canary, probe, GitHub-side scripts and policy)

## Changes

- `.claude/scripts/doctor.py` and `.claude/scripts/doctorlib/`: the standalone doctor (Python 3.9, standard library, no loopctl). Gathering is separated from judging: gatherers read the filesystem, environment, git and recorded `gh api` JSON through injectable seams (`run`, `reach`, `ghapi`, `now`, `fs_root`); about 70 registered checks with stable ids judge the facts. Emits `doctor.v1` JSON (`--json`), exit 0 / 1 / 2. Flags: `--credentials`, `--deploy-surface`, `--level [Lx]`, `--gh-fixture`, `--settings`, `--human-profile`, `--config-ref`, `--claude-version`, `--home`, `--repo`, `--list-checks`, and `--live` (human only; refuses inside a Claude Code session). Never prints a secret value.
  - **Credentials (B2, RC-5):** environment variables (AWS, GitHub, Google, Azure, kube, deploy hosts, registries, SSH, git-config injection, password-manager sessions, database URLs and passwords, `TF_*`), AWS profiles and SSO/CLI/login caches, `gh` `hosts.yml`, git credential helpers/extraheaders/URL credentials at system, global, local, worktree, submodule and per-worktree level, `~/.git-credentials`, `.netrc`, SSH agent sockets and `SSH_AUTH_SOCK`, private keys (encrypted vs not, including OpenSSH-format cipher detection), `IdentityFile` keys outside `~/.ssh`, docker/podman sockets, registry logins, remote docker contexts, kube contexts and in-cluster tokens, gcloud/Azure/Terraform/Vault/Fly/Vercel/Netlify/Wrangler/doctl/Pulumi/Firebase/Supabase/Stripe/Heroku/Helm files, npm/Yarn/Bun/PyPI/pip/Poetry/Cargo/Gem/NuGet/Maven/Gradle/Composer files (home and repo), `pass`/gpg/D-Bus stores, credentials exported from shell startup files, `BASH_ENV`, `.envrc` and `.env`, secret-shaped text in shell history, production env files and keys in the working tree, metadata-endpoint reachability (injectable, only with `--live`), root-equivalent groups, passwordless sudo, and an honest `cred.same-user` notice. Live-only: `sts get-caller-identity` per profile, `gh auth status`, `git credential fill`, `ssh -T`.
  - **Deploy surface (B5, RC-1):** workflows (trigger classification: main vs bot-pushable; deploy commands and actions; one level of indirection through scripts, `make`/`just`/`npm run`, local composite actions and local reusable workflows; external reusable workflows and deploy-named actions flagged as uninspectable), host and CD config files, GitHub Pages, GitOps, Atlantis/Spacelift/env0, IaC detection; a fingerprint of the surface; attestation state `missing | current | stale`; caps L1 (bot-pushable and ungated, or unattested/stale) and L4 (ungated on main).
  - **GitHub (B1, B4, RC-2, RC-9, RC-11):** repo/visibility/plan, rulesets (active, applies to the default branch, required review, code-owner review, last-push approval, required checks and whether they are pinned to an app, force-push/delete), classic protection, **bypass actors** (bot, apps, teams, roles, solo admin in pull_request mode only), Environments (reviewers, self-review), Actions permissions, squash setting, bot permissions, bot identity and PAT lifetime. No data means unknown, and unknown means unavailable unless attested in `platform_attested`.
  - **Settings and tool plane:** `Workflow` allow anywhere is an error except a declared human profile (RC-17), agent definitions granting `Workflow`, `bypassPermissions`, sandbox configuration (`enabled`, `failIfUnavailable`, `allowUnsandboxedCommands`, no docker in `excludedCommands`, deny lists) and its attestation, MCP lockdown (`enableAllProjectMcpServers`, deploy-capable servers and plugins, deny rules), managed settings, web tools denied for the conductor, devcontainer lint.
  - **Secrets (CO-2):** tracked `.env*`/keys/state/credentials, `.gitignore` coverage in one `git check-ignore` call, `.worktreeinclude`, scanner presence, secret-shaped text in kit files. **CODEOWNERS:** parser with gitignore semantics, coverage of guardrail paths, the bot not an owner.
  - **Level (IMP-21):** `min(configured, prerequisites, credentials, sandbox, mcp, b5-deploy-surface, platform, evidence, version)`, each cap printed with its reason; `config.evidence-gate` refuses evidence-gated keys without `docs/baseline/evidence.json`; out of the box the result is **L1**.
- `.claude/scripts/ci_lint.py` (IMP-23): split-CI linter on `kitlib.miniyaml`: OIDC with PR code, secrets in PR jobs (including `secrets['X']`, `toJSON(secrets)`, `secrets: inherit`), privileged triggers checking out the PR, `claude -p` without restoring `.claude`, `.mcp.json`, `plugin`, `.claude-plugin` (and a root `skills/`) from the base ref, `--setting-sources`, script injection, deploys in PR jobs, artifact poisoning, floating action tags, missing permissions. Unparsed workflows are `ci.unparsed: manual review`, never a pass.
- `.claude/scripts/session_start.py`: SessionStart hook. Writes the liveness canary nonce through `kitlib.runstate`, prints it in a context line under 1 KiB, checks the Claude Code version against the `KIT_VERSION` range (banner at L0 to L2, refusal at L3 and above by writing no nonce), announces HALT. Never blocks.
- `.claude/scripts/probe_run.py` (IMP-25): sandboxed first-run probe. Dry run by default; `--go <digest>` runs only if the digest of the printed command list still matches; `docker run --network none --cap-drop ALL`, read-only bind mount, no environment passed; no docker means the commands are printed and nothing runs.
- `.claude/scripts/github/`: `apply-boundary.sh`, `verify-boundary.sh` (thin wrappers) and `boundary.py`. Dry run by default, print every `gh api` call, refuse when `CLAUDECODE` is set.
- `.claude/templates/security/`: branch and tag rulesets (team: no bypass; solo: admin role in `pull_request` mode), `CODEOWNERS.template`, OIDC trust examples (environment-bound, `job_workflow_ref`, plan-preview, drift), a plan-only IAM policy, a devcontainer template, `managed-settings.example.json`, `sandbox.settings.json`, `mcp-lockdown.settings.json`, `mcp.json.example`, `gitignore.snippet`. `.claude/templates/github/workflows/label-guard.yml`.
- `docs/security/`: README, bot-identity, rulesets, credentials, deploy-surface, secrets-policy, supply-chain, mcp, untrusted-content, git-escalation, sandbox, version-policy, infra-human-gate, plus split-ci and first-run-probe.
- Config schema `kitlib/schema/1-boundary.json`; `.claude/loop.config.md` regenerated.
- `.gitignore`: secrets patterns appended at the end of the file.
- Tests: `tests/doctor/` (444 tests, about 20 s on 3.14, 25 s on 3.9), including the five IMP-23 boundary fixtures and an adversarial corpus.
- `tests/kitlib/test_registry.py`: the one-line assertion that the *only* evidence-gated key is `autonomy` became a membership check, because `autonomy_level` (and later `parallel_mode` etc.) are gated too.

## Upgrade impact

None for an installed v1.2.0 copy: new files only, plus new keys in `.claude/loop.config.md` with safe defaults. After upgrading, **the effective level is L1 until a human attests**: run `python3 .claude/scripts/doctor.py --level` and follow the lines that say what blocks the next level. Nothing here edits `.claude/settings.json`; the SessionStart wiring is listed below for the conductor. A project that already has a credential reachable by its agent will see `cred.*` errors: that is the point.

## New config keys

All owner phase `1-boundary`, all H6-protected, none evidence-gated except as noted. Section "Boundary".

- `autonomy_level`: enum `L0 | L1 | L2 | L3 | L4 | L5`, default `L1`. **Evidence-gated for `L4` and `L5`.**
- `github_repo`: string, default empty (owner/name override; empty = derive from `origin`).
- `bot.kind`: enum `none | github-app | machine-user-pat`, default `none`. `bot.login`, `bot.id`, `bot.token_expires`: strings, default empty.
- `solo_maintainer`: bool, default `false`.
- `deploy_triggers`: list of maps, default `[]`. `git_integrated_hosts`: list of maps, default `[]`. `deploy_surface.attested_at`, `deploy_surface.fingerprint`: strings, default empty.
- `sandbox_verified`: string (date), default empty. `agent_isolation`: enum `none | separate-os-user | devcontainer | container`, default `none`. `managed_settings_verified`: string (date), default empty.
- `platform_attested`: list, default `[]` (names: `rulesets`, `code_owner_review`, `required_status_checks`, `bot_no_bypass`, `environment_reviewers`, `apply_human_dispatch`, `g3_ci_only`, `push_rulesets`).
- `factory_approvers`: list, default `[]`. **Registered here because `label-guard.yml` is mine; Phase 11a must not register it again** (a duplicate name is a load error).
- `promotion_attested`: string (date), default empty. `mcp_allowed_servers`: list, default `[]`.

The doctor also *reads* `run_budget_usd`, `runner` and `gates.g4`, which other phases register. It does not register them. Until they exist, setting them is an unknown-key warning (`config.load`).

## Decisions made

- **Package next to the script.** The checks live in `.claude/scripts/doctorlib/` and `doctor.py` is a thin CLI, so each check is a small registered function and the single-step `cp -r .claude .` install still works.
- **Check ids and `emits`.** A check registers one id and may declare the other ids it reports (`emits`, a trailing dot means any suffix). `--list-checks` prints both, and a test fails if any run emits an id that is neither registered nor declared (IMP-22 stable ids).
- **Severity is the outcome's severity.** A passing check is `info`; failures are `error` or `warn`; `unknown` (not probed, not attested) is `warn` and never a pass. Exit 1 means at least one error-severity failure among the shown checks.
- **A crashing check is a failed check** (`error`), never a pass and never a crash of the doctor.
- **`autonomy_level` is a new key; v1 `autonomy` is unchanged.** Default `L1` is today's V1. Evidence-gating `L4` and `L5` by value follows IMP-1.
- **Caps vs prerequisites.** Named caps (credentials, sandbox, mcp, B5, platform, evidence, version) each print their own reason; everything else (bot identity, canary, held-out isolation, App identity, rulesets, required checks, CODEOWNERS, split CI, web tools, managed settings, IaC apply gate, loopctl, spend ceiling, promotion, mutation) is a per-level prerequisite list; the `prerequisites` cap is the highest level whose lists pass.
- **PAT lifetime.** The report says both "fails within 14 days of expiry" and "expires within 14 days (fails past that)". Read as: the expiry must be at most 14 days away (a short-lived token), expired or missing fails, and two days or fewer left warns to rotate.
- **Solo bypass is the repository admin role in `pull_request` mode.** Rulesets cannot name a user as a bypass actor, so the template uses `RepositoryRole` 5; the doctor accepts exactly that on a solo install and nothing else. `solo_maintainer` tells the doctor which install this is.
- **Required checks are pinned to the Actions app** (`integration_id` 15368) in the ruleset templates, because an app with `checks: write` can otherwise post a passing check. The doctor warns when they are not pinned.
- **Tag rulesets.** Tags are releases (H5): solo lets the admin role create them (always mode, because tags have no pull request); team needs `--release-team-id`, otherwise the script skips it and says so.
- **Unknown means unavailable (V27)**, with `platform_attested` as the human override. Rulesets that the API refuses for plan reasons are treated as unavailable, not as an error in the doctor.
- **Unattested means ungated.** A host config file, an unparsed workflow that mentions a deploy, or a CD system the doctor cannot read counts as an ungated deploy until a human attests it. "Unparsed" is never a pass. `fires_on: none` is how a human declares a flagged workflow does not deploy.
- **Fingerprint.** The attestation is bound to a SHA-256 over the deploy-surface files (the H3 floor list, workflows, host/CD configs, scripts workflows run, `package.json` scripts). Any change voids it. The doctor can read `loop.config.md` from a git revision (`--config-ref`) so the base-sha rule of report section 9 applies, and warns when the file has uncommitted edits.
- **Static credential-helper rule.** Any configured git credential helper is an error, because the doctor cannot know what it returns; `--live` clears it when `git credential fill` returns only the bot.
- **The doctor never runs `claude` inside a Claude Code session.** Version precedence: `--claude-version`, `KIT_CLAUDE_VERSION`, `KIT_CLAUDE_BIN`, then the `claude` on PATH only when `CLAUDECODE` is unset. Otherwise the version is unknown and the level is capped at L1. `session_start.py`, which the CLI itself starts, asks `claude --version` and caches it.
- **`--live` is refused under `CLAUDECODE` with exit 2.** The boundary scripts refuse even in dry-run mode, as IMP-15 says.
- **Metadata endpoints are probed only with `--live`.** Without it the result is `unknown`, which holds the credentials cap at L1 unless the sandbox network settings deny 169.254.0.0/16.
- **Hostile-repo hardening.** Doctor git calls pin `core.fsmonitor=false` and `core.hooksPath=/dev/null` and drop `GIT_DIR` and friends; file reads go through `safeio` (regular files only, `O_NONBLOCK`, size cap) so a FIFO or device in place of a config cannot hang or crash the doctor, the SessionStart hook or the probe; text output strips control characters.
- **Sandbox key names.** `sandbox.enabled`, `failIfUnavailable`, `allowUnsandboxedCommands`, `excludedCommands` follow the report; the network and filesystem key names are the report's `denyRead`/`denyWrite` plus equivalent `permissions.deny` rules, and are unverified (V19). The doctor accepts any of those forms.
- **`session_start.py` refusal = no nonce.** The hook cannot refuse a session, so refusal at L3 and above is expressed the way loopctl will enforce it: no nonce, so no dispatch. It reads the configured level from `autonomy_level`; an unreadable config is treated as L1 and says so.
- **`probe_run.py` binds "go" to a digest of the command list** and has no default image. `--docker` accepts a path so tests use a fake; the isolation claim is about the commands under test, not about a caller who chooses the docker binary.
- **label-guard** decides from a repository variable `FACTORY_APPROVERS` (logins), not team membership, because the default token cannot read org team membership. Untrusted values reach the shell only through `env:`. `factory:requested` is exempt so the workflow cannot fight its own relabel.
- **Test speed.** A prebuilt `.git` skeleton is copied per test repo instead of running `git init`, process starts are limited to git by `guarded_run` (so no test can start `aws`, `gh`, `ssh`, `docker`, `sudo` or `claude`), and groups of checks are run singly where only one matters. The doctor suite is about 20 s of the 30 s total; later phases should budget accordingly.
- **`tests/kitlib/test_registry.py`** (Foundations): the evidence-gated-keys assertion became a membership check, as above.
