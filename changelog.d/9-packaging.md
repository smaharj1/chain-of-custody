# 9-packaging: modes become skills, a generated plugin and copy install, `/init`, `/migrate`, `KIT_MANIFEST`

## Changes

- **Commands became skills.** `.claude/commands/*.md` is gone (no thin aliases, IMP-3); every mode is `.claude/skills/<mode>/SKILL.md`: `pm`, `architect`, `tech-lead`, `planner`, `orchestrate`, `bootstrap`, `retro`, plus the new `init` and `migrate`. Frontmatter on all nine: `name`, `description`, `argument-hint`, `effort`; `pm` is model-invocable, the others carry `disable-model-invocation: true` (DEC-17); none forks a context; none is named `loop` or `code-review`. Each body now reads `$ARGUMENTS`. The long modes are split into reference files the skill links to: `tech-lead/` (`lane-a-full-feature.md`, `lane-b-quick-and-review.md`, `telemetry.md`) and `orchestrate/` (`preamble.md`, `loop.md`).
- **Earlier phases' pointers, applied in the skills.** orchestrate: with `runner: driver` the driver runs the loop and the conductor only answers `status --pending-human`; the `pipeline_host` sentence now describes the real key (`conductor` default, `workflow` design-only and an error in the doctor); at an interactive hard stop use PushNotification where it exists, else the hooks snippet; offer `/retro` when an item closes its milestone; with `remote_lock` set and `runner: sequential` run `remote-lock acquire` / `renew` / `release`, never `steal`. pm and tech-lead: a human taking an item by hand runs `loopctl claim take ITEM --by NAME` first and `claim release` after. bootstrap: a "Plugin installs" paragraph (see Decisions). The interview checklists and the numbered preamble from 0b are carried over unchanged.
- **`tools/build-dist.py`** (`--write`, `--check`, `--list`; package `tools/distlib/`) generates, from `git ls-files` only: `plugin/**` (`.claude-plugin/plugin.json` with `userConfig`, `agents/`, `skills/`, `hooks/hooks.json` from `guards/wiring.py build_plugin_hooks`, `scripts/`, `context/`, `spec/`, `templates/`, `docs/`, `evals/`, `seed/`), `.claude-plugin/marketplace.json` (source `./plugin`), `dist/copy-install/**` (the shipped `.claude/`, the Codex and Cursor adapters, the docs the prose points at) and `.claude/KIT_MANIFEST`. In plugin prose, kit paths (`.claude/scripts/...`, `spec`, `templates`, `agents`, kit `context` files, shipped docs) are rewritten to `${CLAUDE_PLUGIN_ROOT}/...`; project paths and globs are not. 661 generated files; a test fails on drift.
- **`tools/validate-plugin.py`** (+ `tools/distlib/validate.py`): the offline stand-in for `claude plugin validate --strict`: manifest keys, `userConfig`, hook events and scripts, no worktree hooks in the plugin, agent frontmatter (no `Bash(...)` in `disallowedTools`, no keys a plugin agent ignores), skill frontmatter and links, every `${CLAUDE_PLUGIN_ROOT}/` path exists, no kit path left unrewritten, no junk, marketplace consistency. `tools/validate-plugin-real.sh` is the human script for the real command.
- **`.claude/scripts/migrate.py`** (`/migrate`): upgrade a copy install to the kit in another folder. Dry run by default. Per file: replace what you never touched, keep what only you changed, `git merge-file` three-way merge when both changed (clean result written, conflict left alone with the marked result in `.claude/.migrate/conflicts/`), remove retired files you never touched, never re-add what you deleted. Classes `kit`, `seed` and `frozen` (`.claude/settings.json`). The base of the merge comes from `.claude/migrate/v1.2.0.tar`, `git archive` of the `v1.2.0` tag. `--apply`, `--resolved`, `--take-kit` are human-only. Backups to `.claude/.migrate/backup/<time>/`; `KIT_VERSION` and `KIT_MANIFEST` move last, only when no conflict is open; re-running is safe.
- **`.claude/scripts/init_project.py`** (`/init`): writes the deny block, the sandbox profile and `enableAllProjectMcpServers: false` into the project's `.claude/settings.json` (additive, nothing of yours changed or removed), seeds the project-owned files from the plugin, writes the plugin's three `userConfig` choices into `loop.config.md` through the key registry, appends the kit's `.gitignore` lines. Dry run by default; `--apply` is human-only and backs `settings.json` up first.
- **`KIT_MANIFEST`** (`.claude/KIT_MANIFEST`, `.claude/scripts/kitlib/kitmanifest.py`): SHA-256 and class per installed file. Ships the files earlier phases asked for: `templates/intake_schema.json` with `intake_validate.py`, `notify.py`, `templates/notify/`, `agents/intake-triage.md`, the unattended, intake and promotion modules, `worktree_hook.py`, `loopctl/parallel/`, `doctorlib/parallel.py`, `templates/parallel/`, `templates/worktreeinclude`, both parallel specs, `loopctl/learning/`, `gates/docs_delta.py`, `docs/learning.md`, `docs/harness-review.md`, `evals/ablation/` (in the plugin), `loopctl/{remote_lock,claims,merge_class,manifest,extras}.py`, `gates/g10_product.py`, `doctorlib/extras.py`, `g10-product.yml`, `spec/loopctl-extras.md`, `docs/loopctl-extras.md`. `tools/evals/ablate.py` is dev-only and not shipped.
- **Guards:** new rule `guard-exec:human-apply`: `migrate.py` or `init_project.py` with `--apply`, `--resolved` or `--take-kit` is denied to every caller, also through `python -m`, wrappers (`sh -c`, `env -u`), variables and `xargs`. 20 corpus rows in `tests/guards/corpus/exec.json` (`exec-187` to `exec-206`); entry in `docs/security/guards.md`. `intake-triage` joins the built-in roster as a critic-class role (`kitlib/caller.py`).
- **Docs:** `docs/packaging.md` (install forms, `/init`, `/migrate`, activating the v2 guards, what a mode is now, maintainer notes).
- **Path sweep (mechanical, allowed for this phase):** `.claude/commands/<x>.md` is `.claude/skills/<x>/SKILL.md` in `.claude/CLAUDE.md`, `AGENTS.md`, the Cursor and Codex adapters, `README.md`, `docs/*.md`, the specs, `examples/hello-loop/kit-overlay/.claude/CLAUDE.md` and `docs/design/probe-assumptions.md`. The default-posture sentence in `CLAUDE.md` now says "per the `pm` skill" so it is true in a plugin project too.
- **Small supporting edits:** `pr_prepare.py init` falls back to the template next to the script when the project has no `.claude/templates/pr-body.md` (a plugin install has none). `tools/check-refs.py` skips the generated `plugin/` and `dist/`. `tests/test_prose_references.py` skips them too and reads a skill as `SKILL.md` plus its reference files.
- **Tests (2594 to 2661; four new modules, each under 4 s even under load; suite 46.7 s wall):** `tests/dist/test_build.py` (24: drift, leak, pointers, manifest, rewrite, write/diff), `test_validate.py` (10: one mutation per check), `test_migrate.py` (19: a decision-table scenario run, human-only rules, tamper, symlinks, hostile archive, and the real v1.2.0 install against `dist/copy-install` with forks), `test_init_project.py` (12), `tests/test_frontmatter.py` (skills in place of commands), plus 20 guard corpus rows. Also run on a real Python 3.9.6.

## Upgrade impact

- **A v1.2.0 install** runs `migrate.py` (dry run, then `--apply` from a plain terminal; `docs/packaging.md`). An unmodified `.claude/commands/` is removed, a modified command stays and is listed; `settings.json` and `loop.config.md` are never touched; agent files you edited merge three-way, and only lines both sides changed are conflicts.
- **The mode files moved.** Anything that read `.claude/commands/<mode>.md` by path (a hand-written note, a hook of yours, a Cursor rule) must read `.claude/skills/<mode>/SKILL.md`. Typing `/pm`, `/orchestrate` and the rest is unchanged. `/architect`, `/tech-lead`, `/planner`, `/orchestrate`, `/bootstrap`, `/retro` can no longer be started by the model itself, only by the person (DEC-17).
- **Plugin installs** are namespaced (`/chain-of-custody:pm`). Loop features that read the kit from git (`runner: driver`, unattended, parallel, the generated GitHub setup script) need the copy install.
- No config key changed.

## New config keys

None. The plugin's `userConfig` (`protected_branches`, `integration_branch`, `main_edit_allow`) reuses registered Phase 2 keys, and `init_project.py` writes them through the registry.

## Decisions made

- **Commands removed, no aliases** (IMP-3). A migrated install that edited a command keeps it; the migration says so.
- **Which modes the model may start.** Only `pm`. `architect` and `tech-lead` are person-started and hand off by words ("switch to `/tech-lead`") after a confirm; the model never invokes the next mode. The five others are human-only for what they change. `argument-hint` and `effort` set on all: `pm`, `retro`, `bootstrap`, `migrate` medium; `architect`, `tech-lead`, `planner`, `orchestrate` high; `init` low.
- **`$ARGUMENTS` is informational.** `orchestrate` treats it as a note for the run; selection still follows the dependency order.
- **Reference files** for `tech-lead` and `orchestrate` only (the two big ones); a skill links every sibling file (a test checks it). The sections the loop must never miss (hard stops, git discipline, the loopctl hand-off) stay in `SKILL.md`.
- **The source of truth stays `.claude/`; outputs are generated and committed** (IMP-3). The build reads `git ls-files`, so an untracked or ignored file can never ship; `.claude/migrate/` (base archives) ships with the kit checkout but is not installed and not in the plugin.
- **The copy install is the shipped `.claude/` verbatim.** The "regenerated adapters" are the root adapters copied in; they were already path-correct for a project root, so no template stage was needed.
- **Plugin layout mirrors `.claude/` one level up** (`scripts/`, `spec/`, `templates/`, `context/`, `agents/`, `skills/`, `docs/`, `evals/`), so scripts that find kit files relative to themselves (`intake_validate.py`, the registry schema) work unchanged. Project-owned files go in `seed/` and are copied by `/init`. The primers and `CLAUDE.md` are never rewritten.
- **Plugin scope.** The plugin covers the interactive modes, the agents, the guard hooks and the stand-alone scripts. The loop machinery that reads `.claude/agents` and the scripts from the project's git history (driver, unattended, parallel) and the generated `setup.sh` need the copy install. Rewriting those for a plugin root would touch a dozen merged phases for a layout the report itself calls "plugin first" only for the modes; documented in `docs/packaging.md`, deferred.
- **Rewrite scope.** Only `*.md`/`*.mdc` are rewritten; JSON/YAML templates are copied verbatim because a human pastes them into project settings, where `${CLAUDE_PLUGIN_ROOT}` does not exist. Hook snippets (notify, worktree) therefore remain copy-install features.
- **`userConfig` is real, not decorative.** Three keys that already exist in the registry; `/init` is the reader (environment `CLAUDE_PLUGIN_OPTION_<KEY>` or `--option`). The guards do not read plugin options (that would let an environment variable set an H6 key).
- **migrate: base from a shipped archive** (`git archive` of the tag, 266 KB), not hashes plus blobs and not fetch-by-hand: it works offline, it is the same bytes the test fixture uses, and a test compares it with the tag when the tag exists (skipped in a shallow clone). The archive covers `.claude/`, the adapters and `skills/`; future bases are one `git archive` line (`docs/packaging.md`).
- **Seeds and settings.** `CLAUDE.md`, `loop.config.md`, primers and rules are replaced only while byte-identical to the base (an unedited template); `.claude/settings.json` is never changed. A kit file that exists in the project but not in the base is a conflict, not an overwrite.
- **Conflicts never touch the file.** The marked merge goes to `.claude/.migrate/conflicts/`; `--resolved` remembers a hash and is forgotten when the file changes again; `--take-kit` backs up first. `KIT_VERSION` moves only when nothing is open.
- **`--apply` needs a clean git tree** (so `git checkout` is the undo) unless `--allow-dirty`, and not while continuing an unfinished migration. `argparse` abbreviations are off for both human-only scripts, so `--app` cannot slip past a guard that matches `--apply`.
- **`/init` writes only additions to deny, sandbox and MCP lockdown**, not the allow or ask lists, not hooks. Allows are a person's (and `/fewer-permission-prompts`' for the interactive lane). If your value differs (`sandbox.enabled: false`) it is kept and reported.
- **Docs shipped = the closure of what shipped files point at** (tokens and relative links), minus `docs/design/` and `docs/baseline/` (maintainer docs). 20 files. Links from a shipped doc to repo-only files (README, tools) do not resolve in an install; check-refs does not scan the generated trees.
- **`/init` shares its name with a Claude Code built-in.** Kept because the report and IMP-3 name it; in a plugin it is `/chain-of-custody:init`. Whether a project skill is shadowed by the built-in is a pending-human probe.
- **Version strings.** The manifest, `plugin.json` and the marketplace read `KIT_VERSION`, which is still `1.2.0`; the release stage bumps it and rebuilds. Because the installed v1.2.0 and the kit share the label before that, a shipped base archive for the installed version wins over "same version".
