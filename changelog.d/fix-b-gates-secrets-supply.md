# fix-b: gates that read untrusted output, secrets and supply chain (review fixes, package B)

## Changes

- **Acceptance verdicts (UN-1, GT-2, D8).** `loopctl/gates/_acparse.py`: `parse()` now always reads the text lines, and (when `allow_json`) EVERY JSON object that has a `results` key, then merges them per criterion with `merge_verdict`, so a failure on any channel wins. A JSON `pass` never upgrades a text or JUnit verdict; a JSON-only `pass` counts only with `allow_json_pass=True`, which `_acrun.run_visible` passes for the G3 visible (`green`) and held-out runs (and for G2's green-on-the-base run of a `characterization` item), never for G6, which calls `parse(..., allow_json=False)`. `Parsed.source` is `text|json|junit|mixed`. A bare `FAIL <id>` line is now a text failure. `g3_acceptance.run_heldout`: a held-out command that does not exit 0 fails with `g3.heldout-failed` (failure class `item`) whatever the output says, so the CI `heldout` job (`gates/_ci.py`) gets the same rule.
- **G5 (GT-5, GT-6, D8).** `_toml_tables` is now a small reader: header spacing and quoting are normalised (`[ tool . pytest . ini_options ]`, `[tool."pytest"]`), a table header is only a header at bracket depth 0 outside multi-line strings (a nested array line can no longer hide the rest of a table), `[tool]` table form and top-level `tool.*` / `tool = {...}` keys are tracked, and anything it cannot classify (unterminated string, unbalanced brackets, unreadable header) makes the whole file count as changed. New always-on lints on lines added to non-test, non-protected, non-doc files: `g5.harness-shaped-output` (error; `"results"` plus an `AC-<x>-<n>` id within a four-line window, committed or untracked) and `g5.hard-exit` (warn; `os._exit(`). New `g5.ignored-config` (error, item class): see `_lib.ignored_problems` below.
- **Ignored files (GT-6).** `gates/_lib.py`: `ignored_files(ctx)` (`git ls-files --others --ignored --exclude-standard`, ignored directories listed once and expanded unless they are dependency directories) and `ignored_problems(ctx)`: an ignored file that matches `CONFIG_GLOBS`, `**/conftest.py`, `*.pth`, `sitecustomize.py`, `usercustomize.py`, `pytest.ini`, `tox.ini`, `setup.cfg`, `.coveragerc`, or is executable, and a TRACKED file marked assume-unchanged or skip-worktree (the same hole from the other side). G5 reports `g5.ignored-config`, G11 `g11.ignored-config`.
- **Evidence and freshness (GT-9, evidence side).** `evidence_gate.py`: a recorded gate with no `head`, outside the pre-build gates (`g0`, `g2`), is `evidence.stale`.
- **G1 (GT-13).** `git grep -z`; the output is split on NUL, so a `:` in a test path no longer reads as an untested criterion.
- **`uncommitted_changes` (GT-14).** Only `docs/features/<slug>/reports/` and `.claude/pr/` are excepted, not the whole feature folder.
- **Secrets (UN-2, UN-3, UN-4).** `kitlib/redact.py`: key names are identifiers, not words: `DB_PASSWORD=`, `API_SECRET=`, `STRIPE_SECRET_KEY=`, `db_password=`, `apiSecret=`, `dbPassword:`, `clientsecret=`, `SECRETKEY=` all match; the closed suffix list (`_key _id _value _secret _token _password _hash _salt _string _data _b64`) keeps `token_budget_per_item: 150000`, `input_tokens: 12`, `max_tokens=4000` and `auth: required` unredacted. `redact_obj` handles camelCase keys. New token shapes: `sk-ant-…`, `sk-proj-/svcacct-/admin-…`, `glpat-…`, `whsec_…`, `pypi-AgEIcHlwaS5vcmc…`, `AccountKey=…` (`ghp_ gho_ ghs_ github_pat_ xox[abprs]- AKIA… AIza… sk_live_ rk_live_ npm_…` were already there). `gates/g11_secrets.py`: unquoted values count in `.env*`, yaml, ini, cfg, conf, properties, toml files and in `KEY=value` lines elsewhere; a placeholder excuses a value only as the WHOLE value; `_added_chunks` reads diffs with `core.quotePath=false`, decodes C-quoted `+++ "b/…"` headers, treats `+++ ` as a header only between `diff` and the first `@@` (an added line that reads `++ b/x` can no longer end a file's scan), reads merge commits with `--cc`, and more than 50 untracked files is the blocking `g11.untracked-overflow`.
- **G9 (UN-7, UN-8).** `gates/g9_supply.py`: a changed spec on an EXISTING dependency is `g9.source-changed` (error; warn when `ext.g9.allow` names it) when it moves to a git, tarball, `file:`, `link:`, `portal:`, `owner/repo`, PEP 508 direct-reference, `{ git|path|url|registry = … }` or Gemfile `git:/path:/source:` source; a plain version bump is unchanged. New `g9.index-changed` (error) for an added or changed `--index-url/-i`, `--extra-index-url`, `--find-links/-f`, `--trusted-host`, `--pre`, `--no-index` in a requirements file; `registry=` and `@scope:registry=` lines in `.npmrc`, `.yarnrc*`, `pip.conf`, `uv.toml`, `.cargo/config*`; `[tool.uv]` index keys, `[[tool.uv.index]]`, `tool.uv.sources`, `tool.poetry.source`, `tool.pdm.source`; Cargo `[patch|replace|source]`; Gemfile `source` lines; go.mod `replace`; npm `overrides`/`resolutions`/`pnpm.overrides` to a non-registry source.

## Decisions made

- **Narrowed exemptions in the ignored-file rule.** The decision says "matches `CONFIG_GLOBS`". `CONFIG_GLOBS` contains `.env*` and `.claude/**`, which are present and ignored in nearly every developer checkout; flagging them would block every sequential run. Exempt: `.env`, `.env.*`, `.envrc`, `.claude/settings.local.json`, `.claude/worktrees/` (other worktrees hold whole checkouts). Dependency and cache directories are skipped: `node_modules .venv venv vendor target dist build` (named in the decision) plus `.tox .nox site-packages __pycache__ .git .next .nuxt .svelte-kit .angular .turbo .cache .parcel-cache .gradle .pytest_cache .mypy_cache .ruff_cache .hypothesis htmlcov coverage`. A listing over 50000 paths is `g5.ignored-incomplete` / `g11.ignored-incomplete` (warn), not a block. A committed `.env*` is still a G5 protected path.
- **`allow_json_pass` is also true for `phase == "red"` when the item's class is `characterization`**, because G2 needs a green run on the base and a JSON-only harness would otherwise never get a pass there. The decision named only the visible and held-out phases; in this code the G3 visible phase is called `green`.
- **`Allowed` is not applied to JSON.** The reviewer asked for it, but a JSON verdict carries no test names to filter on. The stand-in is the merge rule plus G1 (the id must appear in a pinned visible file) plus the G5 lint.
- **`FAIL <id>` at the start of a line is a failure** (was: only `FAIL: `). Strictly more failures, never a new pass.
- **`g5.hard-exit` stays a warning** as decided; `g5.harness-shaped-output` is the error. The harness-shaped lint reads a window of four added lines so a literal split over lines is still seen, and also reads new untracked files from the worktree.
- **Redact key suffixes are a closed list** and bare `auth` / plural `tokens` are not keywords. This departs from the open `(?:[_-][A-Za-z0-9]+)*` suffix in the decision text, which would redact `token_budget_per_item: 150000` (an existing "must stay unchanged" test) and every `*_tokens` usage figure. Strong words (`password passwd passphrase secret apikey privatekey accesskey`) also match when glued to a prefix (`clientsecret`).
- **Quoted values still need a digit and a letter** (unchanged); the whole-value placeholder list is the decision's list plus `$(…)`, `placeholder`, and `example|sample|dummy|fake|test|placeholder|changeme` followed by lowercase words and at most two digits (`example-password-1`), so the repo's existing documentation placeholders keep passing. A scan of every tracked file in the repo with the old and the new `scan()` gives 4 new hits, all fixtures in test files.
- **Unquoted `KEY=value` lines outside config files** need no space around `=`, a value of at least eight characters with a digit and a letter, only value characters (no `(`, `$`, `[`), and not a whole-value placeholder.
- **Held-out exit status:** `exit_code != 0` (including a signal) is `g3.heldout-failed` with class `item`, returned before per-criterion parsing.
- **Extra coverage beyond the decision** (all additive, all errors only in the "can put an unreviewed source in" direction): tracked files marked assume-unchanged/skip-worktree; npm `overrides`/`resolutions`; Cargo patch tables; go.mod `replace`; `.yarnrc*`, `pip.conf`, `uv.toml`, `.cargo/config*`.
- **Third review: the TOML reader tracks state instead of marking `[` lines after the fact.** The reviewer offered two fixes (track depth and quotes, or send every `[` line seen inside an open bracket or string to `unparsed`). The second would flag every nested array and every honest multi-line list; the first reads the file the way the real parsers do and keeps the fail-closed rule for what it cannot place (an unreadable line, a string or array open at the end of the file).
- **Third review: a dotted or quoted key names the dependency by its FIRST part.** `evil.git = "…"` is dependency `evil` with spec `git = "…"` (TOML semantics), so a poetry key that used to be read as the name `zope.interface` is now `zope`; base and head are read the same way, so only the name shown changes.
- **Third review: YAML gets the whole-value read, TOML, JSON and XML do not.** A plain YAML scalar runs to the end of the line, so `,` and `;` belong to it; the other three have no unquoted strings, and the shared cut already stops where their syntax does. A longer reading can only add a finding; a YAML value such as `example,example` that was cut to a placeholder-length word before is now read whole and is a finding (judged an acceptable price).
- **Third review: an `.in` file's lock is any changed pypi `.txt` manifest in its own directory** (pip-compile writes `requirements.txt` beside `requirements.in`, and `-o` is rarely used); a `.txt` elsewhere does not count.
- **Third review: `os.exec*` and `builtins.exit/quit` join the process-ending calls** in G5 (an exec replaces the process, so no runner is left to report); import aliases are collected from the whole file, not per scope.
- **Third review: `<password>` bodies larger than 4096 characters are not redacted by the multi-word pattern**; a one-word value (up to 500 characters) is covered at any padding by the second pattern, and a longer multi-word body is a sentence, not a generated secret.
- **Fourth review: an unreadable file is a finding, and it is `failed`, not `errored`.** `run_gate` already turns an exception into an `error`; the wrappers return a `fail` with the id `g5.unreadable`, `g9.unreadable` or `g11.unreadable` so that the report names the gate and the reason and the failure class is `item` (a human reads the change), not `env` (retry).
- **Fourth review: `MAX_SPANS` is 20000.** More secret-shaped matches than that in one text is one `too-many-matches` hit, which blocks unless the plan allows the path. An honest file does not have that many; a generated one (a lock file of tokens, a corpus) is allowed by `ext.g11.allow`.
- **Fourth review: a bare `$NAME` is a variable and `$NAME/path` is a path.** `DB_PASSWORD=$HOME/.secrets/db` stays quiet. The decision said "pure `$NAME` or `${NAME}`"; the path form was added because it is how such files honestly look. `$$Ab12…` (a compose-escaped dollar) and `$A$Ab12…` are values.
- **Fourth review: `package =` adds the crate it names, it does not make the rename a non-registry source.** The renamed crate then goes through the same checks as any new dependency (look-alike, `dep_check_cmd`), which is what a rename needs.
- **Fourth review: over the 1 MiB limit is an error, not a warning**, because the part that was not read is exactly where a dependency would be put.
- **Fourth review: the `Limits` sections point at the changelog's known-gaps list, not at a file in `docs/`**; they name the fragment until it is merged. The conductor should check the wording after the merge (the fragment is consumed into `CHANGELOG.md`).
- **Fifth review: a path after a reference is judged by its runs, not by its shape.** `$X/Zx81kQm2Pw9L` is a value; `$HOME/.secrets/dbpass12` is a path. The test is a run of 8 or more letters and digits with both cases, or a digit followed by a letter. A lowercase name that ends in digits (`dbpass12`) passes, and so does a lowercase password with trailing digits (`kqmwplzx12`): that is the price of keeping honest file names quiet.
- **Fifth review: a quoted value past 4096 characters is redacted to the end of the line.** Over-redaction is the safe side. A value in an unclosed quote shorter than the bound is still not matched (`password = "Ab12Cd34Ef56` with no closing quote); the unquoted reading needs a character other than a quote.
- **Fifth review: a manifest in another encoding is a finding, not a conversion.** The gate reads UTF-8. A file with NULs (UTF-16, UTF-32) is flagged and left to a human; decoding it would add a second reader to keep honest.
- **Mapping of findings:** UN-1 fixed; GT-2 fixed (same change); UN-2 fixed; UN-3 fixed; UN-4 fixed; UN-7 fixed; UN-8 fixed; GT-5 fixed; GT-6 fixed (limited as decided); GT-9 evidence side fixed (state side is package C); GT-10 documented, no code change; GT-13 fixed; GT-14 fixed.

Known gaps:

- No channel is unforgeable. A product module that prints a text runner line or an all-pass JSON object and then calls `os._exit(0)` can still produce a pass in the held-out and G3 visible runs when no real runner line contradicts it; the rule only guarantees it cannot hide a failure the runner printed, cannot spoof G6 and cannot pass held-out with a non-zero exit. The CI re-run on the merge-candidate tree is the backstop.
- A JSON `pass` for a criterion that has no text line still counts in G3 visible and held-out (the decision's documented-harness contract).
- The harness-shaped lint is a literal-shape check; building the keys or ids with string arithmetic evades it.
- Ignored files inside dependency directories, and ignored `.env*` files, are not scanned. `--index-url` options reached through `-r other.txt` are only seen when `other.txt` is itself a changed `requirements*.txt`.
- The mixed-source reader treats `[tool]` content as one bucket, so any edit inside `[tool]` table form is a protected change.
- Second review, fixed: a dotenv, ini or Dockerfile value is read to the next blank (`DB_PASSWORD=Ab12;Cd34Ef56` was read as `Ab12`; reading to the end of the line would have hidden `ENV DB_PASSWORD=… API_URL=https://…`); Dockerfile `ENV KEY value`; `requirements*.in`; `.yarnrc yarn-path`; the `url-credentials` password bound is 4096 (was 1000). A default in a variable reference (`${DB_PASS:-Xk9mQ2vLp7zR}`, quoted or not) is judged as a committed value; a bare `${NAME}` or `${NAME:?msg}` stays a placeholder. G5 reads the `else` of a main guard. G9: TOML table headers of any length or indentation are headers, and a `[` line that is not a header is an unread table (fail closed, was: joined the table above); the `go.mod` `require (` block is read line by line; every `^\s*` under `re.M` became `^[ \t]*` (a pyproject of blank lines was quadratic). Redact: the blanks after a `secret-element` value are bounded. `g5.runner-shaped-output` no longer fires on a helper named `test_something` that logs `... ok`.
- Second review, still open: a Spring or Jinja default (`${a.b:literal}`) and a quoted default with inner quotes (`"${PW:-"x"}"`) are not judged as values. (`g11.scan` on a 200 KB line with many hits took about 0.5 s because each hit copied the line; fixed in the fourth round, R4-B4.) Of the other items in this bullet in the second round, the nested default, the `[` line inside an array and the `.in` lock are fixed in the third round (below).
- Third review, fixed: R3-GATES-1 (a padded `secret-element` value), R3-GATES-2 (a header-looking line inside an array or a multi-line string hid the dependencies after it), R3-GATES-3 (dotted and quoted dependency keys), R3-GATES-4 (the `_REGISTRY_LINE`, `_toml_list` and `[dependencies]` plus `x = [` quadratics), R3-GATES-5 (YAML values), R3-GATES-6 (go.mod `replace (` blocks), and from R3-GATES-7: nested `${…}` defaults, the `$`-skip for XML elements, `.in` locks, `Containerfile`, import aliases, `getattr`/`__import__` and a module-level call to a function that exits.
- Third review, still open:
  - `g5.module-exit` still misses an exit that is reached through a method (`Tool().run()`), a rebound name (`f = main; f()`), `atexit.register(os._exit, 0)`, `threading.Thread(target=sys.exit)`, `ctypes` and a string passed to `eval`/`exec`. Import aliases are collected from the whole file and applied everywhere (an alias in one function is taken to hold in all of them, which only adds findings). The CI re-run is the backstop.
  - A pip-tools `.in` file compiled to a `.txt` in another directory (`pip-compile -o build/lock.txt`) still raises `g9.lockfile-not-updated`: the rule looks at the directory of the `.in` file only. An honest repository sets `ext.g9.allow` or keeps the output beside the input.
  - A TOML file that is already unterminated at the base (it is not valid TOML, and pip and cargo refuse it) shows the same `unreadable toml` entry at the head, so a dependency hidden in what follows it is not reported as new. A valid file cannot be in this state.
  - `dependencies = { file = [...] }` (setuptools) is exempt from the unread-table rule; the file it names is read only when it is itself a changed requirements file.
- Fourth review, fixed: the structural wrapper, R4-B1 (names and escapes, Cargo `patch`, dotted uv, `uv.toml`, `.cargo/config.toml`), R4-B2 (byte-order mark, manifests past 1 MiB), R4-B3 (`_call_name`), R4-B4 (one pass, hit cap), R4-B5 (bounds redact, `${A}Ab12…`, CDATA), R4-B6 (example keys, `pass`/`auth_key`, escaped quotes, bare references only, YAML parens), R4-B7 (requirement URLs, duplicate specs, go.mod indentation, requirements glob, Cargo `package =`, npm overrides without a cap, Gemfile forms, proxy and certificate keys, `async def`).
- Fourth review, still open (known gaps, by decision; the principle is that the human apply gate is the boundary and these checks are defence in depth):
  - XML `<property name="…password">`, `<entry key="…">` and `<add value="…" key="…">` forms (reversed attribute order, the value in the element body), `<password><!-- c -->…`, `<password><value>…</value></password>` and a comment or child element before the value: a new pattern family with false-positive risk; the CI scanner and the other detectors bound it.
  - `g5.module-exit`: an exit reached through a method, a rebound name (`f = os._exit; f(0)`, `f = lambda: sys.exit()`), `atexit.register(os._exit, 0)`, `threading.Thread(target=sys.exit)`, `subprocess`, `ctypes`, `eval`/`exec` of a string; a user function that shadows `exit` is counted (it needs scope analysis, and errs on the safe side). Import aliases are collected from the whole file.
  - Indirect aliases, commands in scripts, `eval`, `make`, and values laundered through step outputs.
  - A multi-word unquoted YAML value is read up to the first blank (`password: correct horse battery staple`); a backtick inside an unquoted config value is rejected as shell; a password that is a bare `$NAME` shape is taken for a variable.
  - `package.json` `bundledDependencies`, `dependenciesMeta`, `pnpm.patchedDependencies` and `pnpm.packageExtensions`, JSON with comments, Gemfile `gemspec`, `eval_gemfile` and `%w[]`, `go.mod` `toolchain`, yarn `plugins:`, `.npmrc` `//host/:_authToken` lines, Cargo `build =` scripts, and a top-level inline table of tables (`tool = {poetry = {…}}`) are not read as sources.
  - A TOML file whose lines are separated by a lone CR or a Unicode line separator is split by Python's `splitlines`, not by TOML's rules.
  - Any new variant of a pattern class found after this round.
- Fifth review, fixed: R5-B1 (quoted value over 4096), R5-B2 (a repeated spec hid the one between), R5-B3 (`$NAME/tail` with a secret in the tail), R5-B4 (UTF-16 and UTF-32 manifests).
- Fifth review, still open (known gaps, by decision):
  - A manifest in a UTF-16 or UTF-32 file with no ASCII character in it (so no NUL and no byte-order mark) reads as text and is parsed as UTF-8 garbage.
  - A quoted value in an unclosed quote shorter than 4096 characters is not matched.
  - `g11.scan` on one 200 KB line of 12 500 `${NAME}` references takes about 0.36 s (about 30 µs a hit, the same before this round; the same hits on separate lines take 0.05 s). The 4096-character cap on the word read for each hit bounds it; it is not a regex.
- R-GATES-2 stays a literal-shape check: strings built by arithmetic evade `g5.runner-shaped-output`, and the exits listed under "Third review, still open" evade `g5.module-exit`; the CI re-run is the backstop.
- R-GATES-3: an unquoted `DB_PASSWORD = value` in source code is an expression and is not flagged; `password: value` in `.txt` and `.md` is not flagged.
- R-GATES-4: Pipfile, `setup.cfg`/`setup.py`, composer, Maven and Gradle manifests are not read at all.
- R-GATES-6 not changed: `node_modules/.bin` shims (pnpm writes regular-file shims, so flagging them would fail every pnpm checkout) and ignored files under `build`, `dist`, `target` (executables are normal output there) stay unscanned; pytest and unittest do not collect them by default.
- G11 `.json` is now a config file: the fixture `tests/guards/corpus/infra.json` has three scan hits (fake keys in guard test inputs); it needs `ext.g11.allow` if an item ever touches it.
