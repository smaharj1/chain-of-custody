# 10-learning: the learning loop: report conformance (warn, then block), retro, gaps to drafts, critic calibration, the Docs Delta gate, the harness review

## Changes

- **Report conformance** (`loopctl/report.py`, `driver.py`): every problem in an engineer's report or JSON trailer is now **hard** (the decision cannot be read, or the trailer contradicts the report) or **soft** (the form is wrong). `report_trailers: block` fails the item on both, which is what 4a and 4c did; `warn`, the new default, fails it on hard problems only and records the soft ones as `report_warning` events `{item, role, mode, kinds, count}`. A trailer that disagrees with the report, and a last line that is trailer-shaped JSON a strict parser refuses (duplicate keys, `NaN`, deep nesting), are hard in both modes, so a forged or half-forged trailer is never tolerated. `ReportResult.issues`, `.blocking(mode)`, `.warnings(mode)`; an unknown mode reads as `block`. The `gate` event gains `ids` (finding ids of error or warn findings) so a repeating finding can be counted later.
- **`loopctl report scan`**: reads the `report_warning` and `engineer_report` events and the reports on disk; prints how many accepted reports in a row were clean (ten are needed) and says when `report_trailers: block` is ready. Advice only: the key is H6 and a person changes it.
- **`loopctl retro [--milestone M] [--json]`** (`loopctl.retro.v1`): flow, failures by class and reason, the `env` share, rescues (approvals of kind `unblock|env|breaker|cost|demotion`, lock takeovers), per-gate runs and repeating finding ids, spend, report form and brief gaps and deltas by domain, the clean streak, critic precision, unattended stops, `header.demotion`, parallel events, `header.cascades`, how much item time overlapped, and the empty-Primer-Delta streak (L-32: merged items that added a top-level directory or changed a dependency manifest and reported no delta). Every number is a count over a closed vocabulary; no log text appears. `retro.compare(before, after)` is the difference between two retros. `/retro` (`.claude/commands/retro.md`) is the mode that walks a person through it.
- **`loopctl gaps [--write]`** (`loopctl/learning/gaps.py`): finds what repeats in at least `gaps_min_occurrences` items (brief gaps by domain, non-empty Primer Deltas, a gate finding id that blocks different items, an item-class failure reason, `env` failures, report form warnings, a low-precision critic) and drafts rule skeletons (`.claude/rules/<name>.md`, from `.claude/templates/rule.md`) and proposal notes into `<git-common-dir>/loopctl/gaps/gaps-<hash>/` with a README, `COMMANDS.txt`, `PR_BODY.md` and a `MANIFEST.json` with sha256s. It prints the `git switch -c`, `cp`, `git add`, `git commit`, `git push` and `gh pr create --draft` lines for a person and runs none of them (H6). Without `--write` it only shows.
- **Critic calibration** (`loopctl calibration scan|record|report`, `<git-common-dir>/loopctl/calibration.jsonl`): logs each `[BLOCKER]` (or Critical or High security finding) once under an id stable across rounds, derives `fixed` for one a later round no longer lists, takes a person's outcome (`fixed|overruled|false_positive`, `--engineer-hit yes|no|unknown`), and reports precision per critic (`pending` until `calibration_min_samples`).
- **Docs Delta gate** (`loopctl/gates/docs_delta.py`, pure half in `learning/docsdelta.py`): `NAME = "docs"`, `DEFAULT_MODE = "report"`, run with the verify gates after G11. New environment variables, routes and command-line flags in source must be in an added line of prose documentation or `.env.example`, or named in a long enough `## Doc Delta`; otherwise `docs.undeclared`. An empty, whitespace-only, reflowed, punctuation-only, case-only or deleting documentation change cannot satisfy it, nor can an edit under `docs/features/**`, in a test, in the kit's files, or an uncommitted one. `"docs"` joined `gates.KNOWN_GATES` and `driver.VERIFY_GATES`.
- **`loopctl harness [--ablation FILE] [--model ID]`** (`learning/harness.py`) and **`tools/evals/ablate.py`**: the harness review at a model release (`docs/harness-review.md`). Gate owner metrics from real runs plus ablation verdicts (`pending`, `insufficient`, `keep`, `harmful`, `no-effect`, `exempt`) from the eval cases run once as they are and once per part with the part off, graded by `run_local.py`'s graders. A removal needs both to agree; the guards, G5, G9, G11 and the evidence gate are never recommended for removal. `evals/ablation/manifest.json` lists nine parts and their cases; one new eval case, `Q-doc-delta-reported` (`make_synthetic.py` regenerated).
- **Classification** (`cli.py`, `guards/g_exec.py`): reads `retro`, `harness`, `gaps`, `calibration report|scan`, `report scan`; writes (`gaps --write`, `calibration scan --write`, `calibration record`; an unknown `calibration` action) are Tier 1, conductor session only. 42 new rows in `tests/guards/corpus/loopctl.json` (`loopctl-144` to `loopctl-185`).
- New: `docs/learning.md`, `docs/harness-review.md`, `.claude/spec/loopctl-learning.md`, `.claude/commands/retro.md`. One paragraph of `.claude/context/engineer-protocol.md` (section 7) now says what `warn` and `block` mean for a report.
- Tests: `tests/loopctl/learning/` (93 tests, about 2.5 CPU-seconds in all, none over 1.7 s alone): trailers and forgeries, the driver in warn and block, the Docs Delta judgement and the gate on real commits, gaps (detection, drafts, injection, path escapes), calibration, retro and the harness review, the ablation tool, and the commands through `loopctl.cli.main`.

## Upgrade impact

- **A v1.2.0-to-v2 install gains `report_trailers: warn`.** On the serial driver that is a loosening compared with 4a and 4c: a missing trailer, a missing non-Status section or `NONE` without `checked:` no longer fails the item; it is recorded. Set `report_trailers: block` (a reviewed commit) to keep the old strictness.
- `gates.docs` is new and runs by default in `report` mode when the driver runs the verify gates: it records `docs.*` findings on the item and never blocks. Turn it `off` or `on` in `loop.config`.
- `loopctl run` events: `report_warning` is new, and `gate` events carry `ids`. Old readers ignore both.
- Tests that assumed the 4a/4c strictness or the exact gate list were updated (see "Conductor"): the driver's strict report cases now set `report_trailers: block`.
- A copy install that copies hand-picked files needs `.claude/scripts/loopctl/learning/` with `gates/docs_delta.py`; `.claude/` copied whole is enough.

## Decisions made

- **`report_trailers: block` is OPT-IN but not evidence-gated.** The evidence gate (IMP-1) refuses the features that let the loop run with less supervision. `block` is the stricter reading of the same reports and is exactly the 4a/4c behaviour; refusing it until the evidence file exists would make the safe setting the unavailable one. Its cost is availability (an item fails and is retried over report form), not safety. The readiness signal is its own: a clean streak of ten accepted reports (`loopctl report scan`), advice only.
- **What `warn` means.** The 4a/4c reading failed the item on every problem, so a default of `warn` had to mean something specific. A problem is hard when the decision cannot be read or the trailer contradicts the report, soft otherwise. A missing trailer is soft because the report file is the custody artifact and the engineer wrote it; a trailer that is present and wrong is hard because it is an assertion, and the alternative (trusting the first of two readings of a duplicate-key line) is a parser-differential forgery. This loosens the serial driver's defaults (see Upgrade impact); the strict cases of the earlier tests now ask for `block`.
- **The drafts live under the git directory, not in the work tree, and there is no `--out`.** loopctl writing a rule into the tree would be an edit to a guardrail path by a program the human did not read (H6), and `--out` would be a path chosen by the caller. The same findings name the same directory, so a rerun never drafts twice or overwrites a draft a person has edited. The human copies a rule into a branch with the printed `cp`, which is also the moment they read it.
- **A rule is a skeleton, deliberately.** Its words are template text and `<fill>` marks; its file name, its `paths` suggestion (an HTML comment of the plan's own footprint globs) and its "Why" counts come from closed vocabularies and the approved plan. All quoted evidence is in the README and the proposals, fenced and labelled. A rule that reached the model's context with log text in it would be a persistent prompt injection; the cost of the skeleton is that a person has to think, which is the point of DEC-28.
- **Primer changes are proposals, not files.** A primer is edited by the Tech Lead at wrap-up (the primer protocol), and a complete replacement file would need the primer's current content. The proposal names the primer from a closed domain map (`database|backend|app|admin-app|infra` plus the plan's own domains) and quotes the delta.
- **Docs Delta default is `report`.** The gate is a heuristic, so it records until its false-positive rate is known, as the report does for the other new gates. The alternative `on` would have changed every existing driver flow. `"docs"` was added to `KNOWN_GATES` and `VERIFY_GATES`, and the driver tests that list the gates were updated.
- **Docs Delta is satisfied by saying the thing, not by touching a file.** Satisfaction is token-bound: the trigger's own name in an added prose line of at least three words (or a `.env.example` line). A declared Doc Delta passes with a warning because the protocol allows "otherwise report it"; it must be at least `docs_delta_min_words` long and name the trigger, and a whitespace edit changes nothing either way.
- **The primer-staleness flag is in `retro` and not in `loopctl status`.** L-32 says `status` flags it. `status` is read by every caller on every run and the flag needs a diff per merged item, so it is computed where it is used (the retro, `--no-git` skips it). The pure function and its threshold (three structural items in a row) are the same.
- **Ablation covers prompt-level parts; gates are judged by owner metrics.** The eval cases drive a model, not loopctl, so a gate has no case to ablate. `ablation_verdict` accepts a `gate:<name>` part if a project adds a case for it; the review then needs both kinds of evidence to say remove.
- **Safety parts are never recommended for removal by metric** (the guards, G5, G9, G11, the evidence gate): "never fired" is what a working guard looks like, and 16.2 puts a safety regression ahead of any pruning.
- **`/retro` cannot run the write subcommands.** The exec guard allows `gaps --write`, `calibration scan --write` and `calibration record` only to the registered conductor session; an interactive session is not one. The mode reads and asks the human to run the writes (with `!`). Making the write subcommands open to interactive sessions would have widened what an engineer can run.
- **Calibration outcomes are mostly a person's.** Git-visible facts support one derivation (a blocker a later round no longer lists is probably fixed), marked `derived`; overruled, false positive and "did an engineer hit it" are judgements. A person's outcome beats a derived one in either order.
- **New keys not marked H6**: `gaps_min_occurrences`, `calibration_min_samples`, `harness_min_item_runs` only change advice and thresholds of read-only reports; the two that change what blocks an item (`report_trailers`, `docs_delta_min_words`) are H6.

Adversarial attempts, each with a test (`tests/loopctl/learning/`):

- a **forged or half-forged trailer** (status, path or iteration that disagrees; another item's report path; a traversing path; a path in another case; duplicate `status` keys; `NaN`; deep nesting; an extra key; a string iteration; prose after it; a code fence; the Status section removed; an unknown status; a symlinked report): the hard ones fail under both modes, the soft ones are recorded under `warn` and fail under `block`; an unknown mode fails closed;
- a **gaps draft that writes outside its directory or onto a protected file** (`../`, absolute paths, `.claude/settings.json`, hooks, `.claude/scripts/**`, agents, commands, skills, `loop.config`, `.github/**`, CODEOWNERS, `docs/baseline/evidence.json`, `.gitignore`, `.git/**`, `plan/**`, `tests/**`, a nested rules path, an upper-case or over-long name, a NUL, a backslash): every one refused by the shape check and the protected list; a symlinked `files/`, `gaps/` or draft directory; a file standing where the draft would go; exclusive create never overwrites; a forged gap record cannot pick a path; the module starts no process;
- **injected text in the event log, reports and gate messages** reaching a rule (instructions to edit settings, a fake `## Rule`, a tilde fence breakout, an HTML comment, bidi and ANSI characters, NUL, shell metacharacters in a reason or finding id, a domain named like an instruction): none reaches a rule, a file name or a path; all of it is inside a fence longer than any tilde run and labelled; `retro`, `trailers`, `harness` and `calibration` output contains no log text;
- a **Docs Delta gate satisfied by an empty or whitespace-only documentation change** (blank lines, spaces and tabs, punctuation, a reflow, a case change, deletions, the name only in a removed line, a bare name, unrelated words, the feature's scratch folder, a test directory, the kit's files, a code comment, an env example for another variable, an uncommitted edit, a blank or `NONE` Doc Delta, a Doc Delta too short to say anything): none passes; the gate also reads only git objects at the head.
- Found and fixed on the way: `DraftDir` accepted a bare `files` or `proposals` as a file name; `extract_triggers` relied on its caller to drop test and doc paths; a hostile glob in a forged gap record reached the rule's front matter.
